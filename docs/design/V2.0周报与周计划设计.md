# V2.0 周报与周计划设计

确认日期：2026年10月16日；项目标题与跳转更新于2026年10月23日。本文维护已确认规则；当前实现、验收与上线状态见[实施记录](../development/V2.0实施记录.md)。

本文只维护“周报与周计划”入口的已确认设计。入口职责见 [V2.0 产品结构设计](V2.0产品结构设计.md)；[浏览器原型](prototypes/weekly-v2.html)用于体验布局和交互，[源码维护说明](prototypes/README.md)说明如何修改与导出。

## 1. 工作流程与生效方式

项目研发负责人提前整理各项目的执行情况及后续安排，团队负责人集中查看、协调人员工作量并直接调整。默认按项目编排，随时切换人员视角，两种视角共用同一份任务。

- 成员可自行录入本人执行的任务；项目研发负责人可直接安排任务给成员。均保存即生效，进入执行人的工作列表。
- 提前安排和临时插入采用同样的直接保存方式，无需草稿、发布或定稿流程。未来区间的任务可以提前看到，不表示必须立即开始。
- 临时录入的任务在所安排区间展示；“计划外”为第3节规定的可编辑周期标签，原判断条件只用于新建默认勾选。
- 正式项目任务的必填字段、人员属性及权限统一遵循 [项目设计第2节](V2.0项目设计.md#2-正式项目任务)。早期“允许待分配”的设想已由后续项目入口讨论替代；项目、个人工作和区间安排仍引用同一条任务。
- 到达新周期时，未开始、进行中的项目任务若只有过去安排，系统自动追加当前周期，复用原任务并保留旧安排。复制最近一期预计投入（包括明确的0及历史未估算），本期工作留空；系统独立标记“上期未完成 · 自动追加”，不覆盖人工备注。已有当前或未来安排不重复追加、不填补人工计划之间的空档。
- 自动追加按团队维护的连续日期区间运行，服务启动、每分钟检查及读取工作区时补齐；重复执行不重复写入。曾人工取消的本期安排不自动加回。服务停运跨过多个周期时只补当前周期，不凭当前状态倒造中间历史；负责人仍可手动安排其他周期。

## 2. 日期区间与布局

页面顶部按钮顺序为“日期区间 → 文字版 → 里程碑”。进度表和文字版均进入独立的里程碑总览页面，返回保留原区间、筛选及文字状态；里程碑展示偏好、布局、编辑及排序规则统一见 [项目设计](V2.0项目设计.md#4-里程碑)。

- 团队共用日期区间，系统默认按自然周生成，团队负责人可以调整，支持跨月。选择时显示完整起止日期，不以“本周”“下周”作为名称。
- “日期区间”弹窗采用团队共用滑动窗口：默认前1个、当前、后6个区间，共8个；按实际区间顺序计数，兼容人工维护的非七天区间。团队负责人可分别增减两端数量（每次1个，各端0至520个），当前区间始终保留，支持恢复默认。窗口设置独立保存并全团队共享；其他成员只读，已打开页面通过工作区轮询同步。
- 窗口随团队时区的当前区间滚动，保留已保存的前后数量。扩大时优先使用现有区间，不足时只在目录两端补建连续的空区间；缩小只隐藏，不删除区间、任务安排、历史或文字稿。其他页面的日期选择与历史查询仍使用完整目录，不受此窗口限制。
- 增减数量时列表立即变化；目录不足的两端先显示“待保存”日期行，当前和未来的新行可以直接编辑，已结束区间仍锁定。前后端共用补齐规则，未保存前不创建业务记录；范围保存后将新行草稿绑定到正式区间，保留输入并继续核对日期影响。范围保存成功且没有日期草稿时自动关闭；保存失败保留当前内容，有日期草稿时待核对并确认后再关闭。缩小范围不丢弃窗口外新行的日期草稿。
- 窗口与日期草稿独立保存、撤销；窗口配置使用独立并发版本，过期保存提示冲突。编辑日期期间固定当前日期锚点，窗口外的未保存日期行仍显示并标识；跨周不丢失草稿，已结束边界仍受后端锁定。提交日期前须先保存或撤销窗口草稿，日期变更继续走影响预览与确认。
- 日期弹窗采用紧凑单页：顶部用数字框调整向前、向后数量，显示区间总数；下方统一表头列出状态、开始及结束日期，已结束和成员只读日期直接显示文字。省略重复区块标题与常驻规则说明，保留草稿、冲突和错误反馈。底部左侧恢复默认范围，右侧关闭及当前操作：有范围草稿时显示撤销范围与保存展示范围，否则显示核对日期影响，有日期草稿时再显示撤销日期修改。
- 左侧为总结区间，右侧为计划区间。左侧改变，右侧自动选相邻下一个区间；右侧改变，左侧自动选相邻上一个区间。联动按维护后的区间顺序，不固定加减七天。
- 项目双栏顶部对齐，两侧独立按内容撑高；空状态仅显示一行轻提示，不使用深色占位块。批量新增放在任务安排标题旁，窄栏允许换行。两个区间都无任务的项目默认收为紧凑一行，保留展开／收起和安排入口；出现任务后自动展示双栏。
- 历史和未来使用相同的双栏布局。两个日期选择框与下方内容列严格对齐，中间有明显留白；窄屏上下排列并补充区间标识。
- 区间连续、不重叠，选择范围边界时按需要补齐相邻区间。已结束区间的起止日期锁定；当前和未来区间由团队负责人调整，保存前展示受影响的相邻区间、安排、总结及文字稿。不能通过扩大当前区间改动已锁定历史边界。
- 日期边界与任务状态分开：历史区间日期锁定不阻止任务之后继续执行或回退，也不自动冻结当前任务。区间判断使用团队时区。

## 3. 项目与人员视角

### 按项目

每个项目为一组，左右分别展示总结区间的任务完成情况、计划区间的任务安排。任务数量和预计投入用于协调，不能把任务数当作工作量。

项目标题条与项目汇总页共用浅色背景、左侧色条、名称字号及间距，横跨总结与计划两栏，右侧展示当前研发负责人。项目名称带跳转箭头，点击进入该项目的任务页；拖拽把手独立，不将整条标题设为跳转区域。任务数量、完成情况和预计投入保留在各自栏内。空项目继续保留展开与安排入口；排序模式维持整行拖动的紧凑列表。

总结和计划严格按对应周期的有效安排展示，不再仅因任务进行中、曾开始或完成而纳入无排期的周期。每期可显示该安排的本期工作、自动追加标记和“计划外”标签。

“计划外”按“任务＋周期”独立保存，执行人、项目研发负责人和团队负责人可按任务权限随时修改，包括已结束周期；纠正标签不改写任务的历史执行状态，修改前后值及实际操作者保留在操作历史。直接新建正式任务且首次安排到创建时所在周期时默认勾选，未开始也勾选；待建转换、已有任务追加安排及自动延续默认不勾选，但均允许人工标记。不符合默认条件也可人工勾选。周期以团队区间首日上海时间 00:00 为界。

默认只在新建保存时填充；明确取消后，刷新、改派、改期、日期边界调整或里程碑变化均不重新推断。新周期不继承其他周期的标签；取消后重新加入同一期保留原值。旧数据一次性固化原判定结果，来源不足继续显示“计划性不可还原”，人工确认后使用保存值；不补发迁移通知。新建、批量新增、待建转换与详情共用周期勾选项，宽屏日期、投入、本期工作、计划外及取消操作同排，窄屏换行；总结与计划侧均展示保存的标签。单独修改标签不要求补填历史未估算投入。

已结束区间显示区间结束时的状态；当前区间显示截至当前的执行事实。例如上期安排且本期自动追加、本期完成的任务：上期显示当时尚未完成，本期显示完成。之后重开不会回写这两个历史状态；显式修改实际完成时间可以纠正对应周期的完成状态，审计仍保留真实操作时刻，边界见[项目设计](V2.0项目设计.md#投入与完成结果)。汇总与任务详情区分“区间结束时状态”和“当前状态”。

截至回看时刻该区间已无有效安排，则不展示在该区间总结中，适用于所有状态。当前区间以当前时刻判断，已结束区间以结束前的状态和安排判断，之后改期或回退不改写已结束区间；周期内已移除的任务不会仅因周期结束重新出现。操作与安排历史继续保留；显式补录完成时间撤销的无效自动追加除外。

计划侧仅保留连续加行批量新增入口，指定执行人、优先级和必填的预计投入人天。已有任务延续到后续区间，在任务详情中追加安排并填写投入。入口位于计划列表上方，批量新增每行独立维护日期区间和关联里程碑，默认带入计划侧区间。预计天数表示该任务在所选区间内预计投入的工作天数，不是任务总工期。历史未填写值单独提示，不按零工作量处理；新提交的安排不能留空。优先级使用 1 最高、2 高、3 中、4 低、5 最低，默认 3 中。

### 按人员

每个人同样分为左右两栏：左侧总结区间的完成情况，右侧计划区间的任务安排。各栏内部按项目分组，右侧汇总任务数、已估算天数及未估算任务数，便于识别跨项目安排。调整任务后两个视角同步。

各栏内的项目名称也带跳转箭头，点击进入相同的项目任务页；保留人员视角的紧凑分组层级，不重复展示完整项目标题条。

## 4. 编辑、取消安排与删除

点击任务名称打开共用任务编辑弹窗，维护名称、执行人、状态、优先级、各周期安排及预计投入、关联里程碑和整条任务的完成结果，创建人只读。全部安排保留，预计投入与周期逐行对应；各入口的排列规则统一见[组件与交互规范](V2.0组件与交互规范.md#4-表单与详情)，不将入口区间置顶。任务状态为未开始、进行中、已完成；不因文字模板引入累计进度百分比字段。完成结果及按字段授权统一遵循 [项目设计](V2.0项目设计.md#投入与完成结果)。

上述为具备管理权限的编排视角，执行人不因此获得全部字段的编辑权限；共用字段与权限遵循 [项目设计](V2.0项目设计.md#2-正式项目任务)。取消安排必须满足正式任务至少保留一个区间的约束。

已确认禁止直接取消最后一个区间安排，显示原因并允许改排到其他区间；不自动退回待建任务。其他区间的取消进入明确确认视图；返回保留任务编辑草稿。修改当前安排区间时保留其他区间，目标区间已有关联则提示直接编辑已有安排，不静默覆盖。

| 操作 | 含义 |
| --- | --- |
| 取消该区间安排 | 只取消选定区间与任务的安排关系，任务本身及其他区间安排保留，可再次选择加入；不是转移到另一个区间。 |
| 删除任务 | 删除整条任务及各区间关联安排，确认前显示任务名称与涉及区间；手工文字按第6节保护，不静默改写。 |

当前区间截至当前时刻已删除的任务不再展示在总结、任务计数和自动文字中，未来安排也不再展示；周期内删除的任务在周期结束后不会重新出现。已结束区间仍按结束前的状态回看，之后发生的删除不改写先前事实，审计事件继续保留。

这些是 V2.0 设计语义，不代表原系统已发布历史、审计记录或数据库可以直接物理删除。权限及历史契约见[研发需求](../product/研发需求说明书.md)，旧数据转换见[迁移准备](../development/V2.0迁移与研发准备.md)。

## 5. 排序

默认、新任务置顶、恢复默认及跨页面隔离见[统一排序规则](../product/研发需求说明书.md#统一默认排序与手动排序)。项目组顺序由团队跨所有周期共用，切换总结或计划区间保持一致，左右列一致；任务顺序按项目和区间保存。恢复入口分别作用于当前项目组列表或项目整个区间（包括人员筛选外任务）。

周计划排序由团队共享，不是个人偏好；个人看板顺序保持独立。团队负责人维护跨项目组顺序，项目内任务顺序由团队负责人或本项目研发负责人维护。筛选或受限视图的排序不能删除、覆盖不可见项目的顺序；多人冲突不能静默覆盖。

- 项目整组拖拽，左右列保持一致；任务仅在同一项目、同一日期区间内拖拽排序，不通过拖拽改变项目归属、负责人或排期。
- 文字自动生成时沿用项目和任务顺序，项目内编号从 1 开始。已手工编辑的文字遵守第6节的更新提示规则，不自动重排。
- “项目排序”模式展示全部项目的紧凑列表，任务内容暂时收起，整行可拖动；点击“完成排序”恢复双栏及原筛选。正常视图保留项目拖拽把手。恢复项目默认排序收进该模式工具栏的“⋯”；任务恢复入口放在所属内容标题右侧的“⋯”，不单独占行。
- “按人员”提供同样的“人员排序”紧凑列表及姓名旁的拖拽把手，左右内容整组移动；“⋯”恢复所有周期的人员默认顺序，完成后恢复原项目筛选。权限、默认顺序与持久化范围沿用[统一排序规则](../product/研发需求说明书.md#统一默认排序与手动排序)。
- 拖拽时原行保留尺寸，其他行平滑让出目标位置；浮层跟手，靠近内容视口边缘渐进滚动。放到无效范围或按 Escape 时取消；把手支持上下方向键排序。松手立即显示新顺序，保存期间拦截重复操作；失败撤回预览并显示错误。

排序与文字版的当前实现、浏览器验证及发布边界见[实施记录](../development/V2.0实施记录.md)。原型尚未同步 2026-10-19 的紧凑空状态、菜单收拢和文字版弹窗，不作为当前交互验收证据。

## 6. 文字版

页面顶部保留统一的“文字版”入口，打开大弹窗查看当前两个日期区间的完整文字，支持编辑和一键复制。弹窗固定打开时的区间组合，内容区独立滚动，标题与底部操作保持可见；编辑、保存、复制与重新生成统一放在底部，预览替换操作跟随预览区。关闭未保存草稿时须提示，轮询不能覆盖草稿。项目卡片内不再放“成果与问题”“安排重点”；项目页不新增文字版入口。

默认模板为：

```text
总结区间的完整起止日期
山东
1.任务名称 负责人
2.任务名称 负责人
济南
1.任务名称 负责人

计划区间的完整起止日期
山东
1.任务名称 负责人
数字专家
1.任务名称 负责人
```

区划名称在该示例中就是项目名称。自动生成时一条任务对应一行、一个负责人，编号在每个项目内重置。有本期工作时生成 `1.任务名称（本期工作） 执行人`，未填写时省略括号。总结使用总结周期截止时的工作内容，计划使用计划周期的工作内容，同一任务不同周期不混用；本期工作变更沿用手工稿保护和重新生成规则。可以手工把多条任务合并表述，或补充 `100%`、`80%` 等描述，但不反向修改任务，也不新增系统进度字段。

| 状态或操作 | 行为 |
| --- | --- |
| 尚未手工编辑 | 随相关任务、安排和排序自动更新。 |
| 已手工编辑 | 保留用户文字，相关任务、负责人、安排、日期或排序发生变化时提示“任务安排有更新，文字版尚未同步”。 |
| 重新生成 | 先展示新内容，原文仍保留；确认替换后覆盖原文并恢复自动更新；取消则保留原文。 |
| 手工核对 | 可继续编辑原文，核对无误后保留当前文字；后续相关变化仍需提示。 |
| 复制 | 复制当前显示的保留文本，不暗中生成另一份；未同步时保留提醒。复制失败时选中文字并提示快捷键，不虚报成功。 |

正式文字稿按“团队＋总结区间＋计划区间”的组合共享保存，由团队负责人查看、编辑和维护，切换组合不串内容；团队负责人生成时覆盖全团队项目，页面筛选不缩减范围。其他人只生成、查看和复制本人有权项目的文字，不维护团队共享稿，也不直接读取可能混有无权项目的共享自由文本。保存文字后如果来源仍与编辑前不同，不自动清除未同步提示；需核对或重新生成。预览后来源再次变化，要更新预览并再次确认，不能替换成过时内容。

## 7. 原型与正式实现的边界

原型覆盖双栏、项目／人员视角、日期联动、选择／批量新增／编辑／取消安排／删除模拟任务、排序、文字同步和复制。示例任务与日期用于演示，不是生产事实；模拟任务、手工文字、日期调整和排序刷新后不保留，查看偏好可能由预览环境记住。

已进行浏览器交互检查，包括实际指针拖拽、键盘排序、无效拖拽取消、文字保护及重新生成、日期双向联动；落库时再次检查紧凑项目排序、导出文件打开及窄屏布局。检查不证明后端权限、数据库、并发、Electron 或生产功能已实现。

共享范围、权限、区间统计与日期锁定按本文执行，不能继续列为未决产品规则。正式研发仍须落实事件模型、版本冲突和旧发布数据映射，见[研发需求](../product/研发需求说明书.md)及[迁移准备](../development/V2.0迁移与研发准备.md)。原型的当前状态统计、模拟日期修改和内存文字不证明这些能力已实现。
