# V2.0 团队管理设计

确认日期：2026年10月16日；首页标语规则更新于2026年10月19日。本文维护已确认设计，当前实现、验收与上线状态见[实施记录](../development/V2.0实施记录.md)。

本文维护“团队管理”入口的功能边界与成员配置规则。入口职责见 [V2.0 产品结构设计](V2.0产品结构设计.md)。设计参考现有团队管理页面及后端实现，作为 V2.0 开发基线的一部分，不代表线上行为已改变。

## 1. 入口职责与权限

- 团队负责人维护团队成员、项目基础信息、项目角色和项目成员。
- 保留“成员”“项目”两个页签，取消小组、组长及小组归属配置。
- 团队管理员维护“我的工作”顶部的可选团队文案，见第5节；本轮称呼沿用团队负责人这一管理角色，不新增独立权限角色。
- 项目任务、里程碑和待建任务仍在“项目”入口维护；团队管理提供进入项目的入口，不重复建设业务页面。
- 取消独立的归档、交接流程入口；项目成员移出直接在成员配置中处理，约束见第4节。
- 系统管理员保留基础账号、团队管理，并可从同一侧栏进入项目和周报与周计划；账号编辑提供系统管理员角色选择，团队选择与权限边界统一见[研发需求](../product/研发需求说明书.md#3-账号会话与-token)，不将项目成员移出规则扩大为团队成员移出或账号停用规则。

## 2. 成员管理

沿用现有页面的成员表格和账号维护能力：

- 展示账号、姓名和启用状态，支持按账号或姓名搜索、按状态筛选。
- 支持创建成员账号、添加已有账号、重置密码、启用和停用。
- 简单新增及维护操作使用弹窗；信息量大的名单配置可在当前页面工作区完成，账号相关权限与校验沿用现有规则。按钮位置、去重与返回约束统一见 [组件与交互规范](V2.0组件与交互规范.md)。

团队成员移出不属于本入口列明的操作，V2.0 不保留旧独立交接入口。账号停用继续撤销访问并保留任务、里程碑及历史，不自动转交、完成或删除工作；不得把第4节项目成员移出检查套用于账号停用。

## 3. 项目配置

### 项目与负责人

- 创建项目时填写项目名称，必须指定项目经理和项目研发负责人。
- 每种负责人角色允许多人，但至少保留一人；同一个人可以兼任两种负责人角色，也可以兼任研发人员。
- 指定负责人时自动纳入项目成员，不需要重复添加；同一个人只占一条成员记录，保留其多个角色。
- 其他成员从本团队可用成员中选择，沿用现有成员多选、同一行配置角色的方式。
- 后续修改角色或移出成员时，同样必须保证两种负责人角色都至少有一人。

### 页面组织

项目列表展示项目名称、项目经理、项目研发负责人和成员数量，提供编辑、管理成员、进入项目操作。新增、编辑使用弹窗；成员较少时使用宽弹窗，复杂名单及阻塞项需要对照时允许使用当前页面工作区。新增位于列表顶部，编辑与成员操作贴近对应行，底部操作组居中，关闭在组内最左侧，其他业务操作在中间，保存在最右侧；右上角保留快捷关闭，返回入口位于左上角。

成员配置支持搜索、多选和角色调整；负责人支持多人，因此创建与编辑表单不能将每种负责人限制为单选。

## 4. 移出项目成员

由团队负责人在项目成员配置中直接操作，不另设交接流程。移出前必须满足以下条件：

| 检查项 | 处理规则 |
| --- | --- |
| 该成员在本项目有未完成任务 | 先调整为其他执行人，再允许移出；不自动变为待分配。 |
| 移出后某种项目负责人角色无人担任 | 先指定其他成员承担对应角色，再允许移出。 |

检查只针对当前项目，不要求处理该成员在其他项目中的工作或私人任务。条件未满足时，直接列出待调整的任务或缺少的负责人角色，便于处理后重新操作。

移出仅解除当前项目成员关系，不删除账号和历史工作记录。已完成任务保留原执行人，里程碑不设置人员归属，其他历史记录保持原样，不因移出而批量改写。

## 5. 团队文案

“我的工作”时间问候下方展示一条随机首页标语，由团队负责人在“团队管理 → 首页标语”维护。普通成员只读，不新增管理角色。

- 支持新增、修改、删除多条纯文本标语，修改后统一保存；每个团队最多 50 条，每条最多 500 字。保存时去除首尾空白，忽略空白条目。
- 每次进入或刷新“我的工作”时，从当前团队列表等概率随机选择一条，允许连续抽中同一句；无需额外请求。搜索、筛选、拖动、任务操作及后台轮询不重新抽取，离开页面后再次进入才重新选择。
- 当前展示句被删除或修改后，在下一次配置数据同步时从最新列表重新选择；仅添加其他句子时保留当前句。
- 未配置、全部删除或只剩空白内容时隐藏文案，不显示默认替代句、空行或提示；按时间变化的问候与姓名仍保留。不增加轮播或自动生成流程。
- 后端按次验证团队负责人权限，并用团队配置版本防止并发覆盖；冲突时保留草稿并提示刷新核对。
- 原有单条非空文案迁移为列表第一条，空值迁移为空列表。“今天一定，别让产品名赢了。”仅为原型示例，不是默认内容。

展示设计见 [V2.0 我的工作设计](V2.0我的工作设计.md#5-页面布局与问候区)。

## 6. 2026-10-16 设计时的实现参考与改造边界

以下保留设计时的核对背景，不代表当前交付状态；当前证据见[实施记录](../development/V2.0实施记录.md)。

| 内容 | 本轮核对结果与 V2.0 方向 |
| --- | --- |
| 创建项目必须指定两种负责人、允许兼任、自动加入成员 | 现有实现已具备，沿用。 |
| 成员多选、同一行配置多个角色、每种负责人至少一人 | 现有成员维护已具备，沿用；创建项目的负责人选择需扩展为多人。 |
| 小组与归档、交接入口 | 现有页面仍有这些入口，V2.0 按本设计移除。 |
| 项目成员直接移出及任务、角色前置检查 | 作为 V2.0 改造要求，不能视为现有页面已支持。 |
| 项目列表信息及编辑入口 | 按第3节调整，属于设计目标。 |

后续研发需验证权限、并发修改、负责人角色保留、未完成工作检查及历史记录保留；本次仅落地设计文档。
