# V2.0 我的工作设计

确认日期：2026年10月16日；私人子任务、完成日期筛选及日报更新于2026年10月22日。本文维护已确认设计与交互原型，当前实现、验收与上线状态见[实施记录](../development/V2.0实施记录.md)。

本文维护“我的工作”入口的设计规则。入口职责见 [V2.0 产品结构设计](V2.0产品结构设计.md)，[浏览器原型](prototypes/my-work-v2.html)用于体验交互，[原型维护说明](prototypes/README.md)说明源码与导出关系。本文属于 V2.0 开发基线，不表示正式网页、桌面或生产行为已经改变。

## 1. 任务来源与权限

项目任务与个人任务共用一个分类看板，卡片标明所属项目或“个人 · 仅自己可见”，支持搜索及来源筛选。

| 内容 | 设计规则 |
| --- | --- |
| 项目任务 | 分配给本人后直接显示，不再手动领取、加入个人空间或复制成关联个人事项。与项目、周计划引用同一条任务，状态同步。 |
| 成员自行创建项目任务 | 在本人参与的项目内创建，默认由本人执行；保存后遵循项目任务权限。 |
| 个人任务 | 允许不属于任何项目，仅本人可见、维护，不进入团队周计划或项目汇总。 |
| 负责人代改状态 | 团队负责人、项目研发负责人可在管理范围内代改开始、完成或回退，记录实际操作者；同步到执行人对应状态的默认分类。 |
| 项目任务编辑 | 执行人可调整状态、已有周期预计投入和完成结果，详见[项目任务投入规则](V2.0项目设计.md#投入与完成结果)；个人分类和顺序由本人整理。名称、执行人、优先级、日期区间和里程碑仍由有管理权限的负责人维护。 |
| 项目任务删除 | 创建人可删除自己创建且当前为“未开始”的任务，不额外检查是否曾经开始。团队负责人、项目研发负责人可删除管理范围内的任务；执行人身份本身不赋予删除权限。 |
| 个人任务编辑、删除 | 本人自由维护，删除前确认。 |

任务状态为未开始、进行中、已完成，允许回退。任务不设置说明、团队共享检查清单和独立进展记录；私人一层子任务见第6节。原有分工拆成多个个人事项的联动方式不沿用到 V2.0。

个人任务需要纳入项目工作时，应通过明确的转入操作处理，不能靠拖动个人分类改变归属；转换字段、校验与历史处理尚未细化，当前原型不提供此操作。

## 2. 分类与默认分类

### 分类对应执行状态

- 默认初始化“未开始、进行中、已完成”三个分类；分类名称可以自定义。
- 每个分类对应一种执行状态，同一状态可以有多个分类，例如“开发中、等待联调”都对应进行中。
- 分类独立于项目，同一分类可放不同项目的任务和个人任务。
- 跨分类拖动时按目标分类更新状态；同状态分类之间移动不改变状态。项目任务进入完成状态分类先填写完成结果，确认后同时保存状态和指定落点，取消保留原位置；已完成任务在完成分类之间移动不重复填报。
- 每种状态至少保留一个分类；已有分类只提供改名，不通过改变分类所属状态批量修改任务。

### 每种状态一个默认分类

每种状态必须且只能指定一个默认分类。初始三个分类各自为默认，不额外建立固定“未分类”列。

| 场景 | 进入规则 |
| --- | --- |
| 新分配给本人的项目任务 | 按任务当前状态进入对应默认分类，放在分类顶部。 |
| 新建任务 | 默认选择未开始状态的默认分类，允许创建时明确选择其他分类。 |
| 点击开始 | 进入进行中状态的默认分类。 |
| 点击完成 | 项目任务填写完成结果后进入已完成状态的默认分类；私人任务直接完成。 |
| 点击重新打开 | 进入进行中状态的默认分类；需要回到未开始时，通过拖动或详情选择。 |
| 从其他入口同步状态变化 | 进入新状态对应的默认分类。 |
| 其他字段变化、状态未变 | 保留个人分类和顺序，不移回默认分类。 |
| 手动拖动或明确选择分类 | 以用户选择为准，不改放默认分类。 |
| 更换默认分类 | 仅影响之后的自动进入，不搬动已有任务。 |

新增或通过快捷操作进入某分类的任务按该分类当前排序规则排列；手动拖动遵循明确落点。默认规则替代此前“同状态多个分类时每次弹窗选择”的方案。

### 分类维护入口

- “新增分类”与“新建任务”并列放在顶部，以低强调按钮展示。
- 每个分类标题旁放“⋯”，提供修改名称、设为默认、删除分类，不再集中展示逐行编辑的大表单。
- 新增只填写名称、对应状态，可同时勾选设为默认；分类名称不重复。
- 分类标识只写“默认”，悬停、聚焦或触摸查看完整说明，包括自动进入、手动选择优先及更换默认不搬动任务。
- 删除分类时保留任务，并明确选择同状态的接收分类；若删除的是默认分类，所选分类同时接替为默认。该状态最后一个分类不可删除，并显示原因。

## 3. 排序与拖动

- 看板始终允许手动排序，不再设置“优先级／手动”模式切换。
- 分类标题可拖动调整整列顺序，顺序仅本人可见并持久保存；不改变分类状态、默认设置及列内任务顺序。“恢复默认排序”仅恢复任务排序，保留分类顺序。分类标题聚焦后可用方向键调整。窄屏纵向排列时按上下顺序调整。
- “恢复默认排序”对本人所有分类生效，包含筛选外任务；之后仍可随时拖动。默认、手动、新任务置顶和升级保留规则见[统一排序规则](../product/研发需求说明书.md#统一默认排序与手动排序)。
- 优先级为 1 最高、2 高、3 中、4 低、5 最低，默认 3 中。
- 拖动明确指定落点后，目标分类保存为手动顺序；其他分类保持各自的排序规则。
- 个人排序不修改项目页、周计划的排序，也不修改任务优先级。筛选只改变可见范围，不丢失隐藏任务。
- 拖动时卡片跟随指针，原位置与目标位置通过占位反馈，周围卡片平滑让位；靠近看板边缘自动滚动，放下后落到目标位置。
- 鼠标可从任务标题、顶部及空白区域起拖，操作按钮仍执行原操作；触屏从任务顶部或分类标题起拖，其他区域保留页面滚动。放下即时显示目标位置，保存中阻止重复移动，失败恢复服务器位置并提示；分类拖动使用同样的反馈与取消规则。
- 无效落点、Escape 或指针取消保持原任务位置。卡片不再提供“移动”按钮，状态仍可通过卡片操作和详情维护；减少动态效果偏好下不播放让位和落下动画。

## 4. 展示范围与完成区间

- 默认展示所有未完成任务，不受日期区间限制，避免遗漏积压工作和未来已安排任务。
- 已完成任务按本次实际完成日期筛选，支持“按日期”和“按日期区间”；新账号默认按日期展示当天。按区间沿用团队已有日期区间，使用完整起止日期，支持全部及无法还原完成日期的历史记录。
- 模式切换收在已完成分类的“⋯”内，列内只展示当前模式的日期或区间选择；按天提供前一天、后一天和今天。多个已完成分类共用筛选，不影响未完成分类。
- 每个账号在服务端记住模式，网页与桌面共用。重新进入页面时按日期回到当天、按区间回到当前区间，不记住上次临时选择的历史日期。
- 任务恢复未完成后离开完成列；再次完成按本次完成日期归入相应区间。正式实现仍需保留历史状态事实，不能直接用原型的字段覆盖方式处理审计数据。

## 5. 页面布局与问候区

- 弹窗、按钮及任务表单的共用展示规则见 [组件与交互规范](V2.0组件与交互规范.md)。短表单使用同层弹窗；底部操作组居中，依次为关闭、删除等其他操作、保存或确认；右上角保留快捷关闭，返回与关闭均保护未保存内容。
- 顶部保留较小的“我的工作”页面标识，主要标题为按时间变化的问候与本人姓名，例如“早上好，解鹏”。问候固定按北京时间，页面停留期间到点更新，后台恢复时重新校准。
- 问候下方展示可选的团队文案，维护权限和空值规则统一见 [团队管理设计：团队文案](V2.0团队管理设计.md#5-团队文案)。未配置时不展示该行，也不留占位；时间问候仍保留。
- 右侧依次为带文档图标的“我的日报”、新增分类、新建任务。我的日报与新增分类使用同样的低强调按钮；下方为搜索、项目／个人筛选及恢复默认排序。
- 主体沿用分类看板，桌面端分类列铺满视口剩余高度，内容增加时自然向下展开；采用接近页面的背景和淡分隔线，窄屏纵向排列并按内容撑高。默认标记放在分类标题旁，完成日期筛选保留在已完成列顶部。
- 卡片按来源与优先级、任务名称、日期与操作三层紧凑展示；移除“移动”按钮，保留拖拽。开始／完成／重新打开始终位于底部右侧，与日期同一行；开始配轻量播放图标，日期过长时允许换行。点击名称打开详情弹窗。空列提示靠上展示，整列仍是拖拽落点。
- 页面底部不常驻操作说明、排序提示或状态展示。操作结果使用短暂反馈，分类规则放入悬停说明或对应操作内。

## 6. 私人子任务

- 本人执行的项目任务和个人任务均可维护一层私人子任务。只包含名称及完成/未完成状态，最多200条，不设人员、日期、工时或多级关系；不进入项目、团队周计划、团队周报及任务统计。
- 主任务卡片仅在开始／完成／重新打开左侧放低强调“子任务”按钮，不显示数量、不在卡片展开。管理弹窗展示完整列表，支持新增、改名、勾选、删除、拖拽及上下方向键排序，统一保存。
- 删除先确认具体子项，返回清单后保存才生效。关闭、返回与离开页面保护草稿；读取失败、归属变化或版本冲突不得覆盖已有清单。
- 主任务与子任务状态独立：全部子项完成不自动完成主任务；主任务完成或重开不改变子项。子项完成时间由服务端记录，改名、排序不改变时间，取消完成再完成记录本次时间。
- 只有当前执行人可读取和维护自己的清单，负责人不能代看或代改。主任务改派后，新执行人使用自己的清单，原执行人的内容不会转交；原执行人仍保留本人历史日报事实。主任务删除不清除历史快照。

## 7. 我的日报

- 仅本人可见，默认当天，按上海自然日查看当日完成清单。完成筛选和日报日期互不影响；支持前后一天、今天、手选日期。
- 收录所选日完成的主任务，以及所选日完成的子任务；父任务未完成时仍带出其名称作为子任务上下文，不列未完成步骤。父任务和子项合并展示，不将子任务重复算作主任务数量。
- 按项目分组，默认跟随项目页共享项目顺序；个人任务固定在项目之后。“⋯”内可拖拽设置本人项目顺序，跨日期和设备使用，也可恢复跟随项目。个人配置不修改共享顺序，新增项目追加到个人顺序末尾。已撤权项目不在当前排序列表中，但本人当时的完成事实可在历史日报展示。
- 日报正文直接从项目分组开始，不输出“日期 日报”标题；日期仅在上方日期选择器展示。每个项目内主任务使用 `1.`、`2.` 编号；子项按保存顺序使用 `（1）`、`（2）`。不附加“当日完成”“未开始”“进行中”标签，展示、复制和重新生成使用同一正文格式。
- 内容使用所选日末的本人执行及子任务快照；当前日随有效保存更新。之后日期的改名、删除、取消完成、重开及改派不回写过去日期。没有可还原的完成时间或历史证据时不补造日报事实。旧快照缺少项目名时，只能使用当前有权项目名或“历史项目”。
- 大弹窗复用周报文字版的展示、编辑、复制和重新生成预览。手工稿按账号和日期保存，来源变化保留文字并提示；重新生成须预览并确认，来源或文字版本变化拒绝旧请求，支持核对后保留原文。复制当前显示的文字，编辑时不能切日期丢失草稿。

## 8. 原型与正式实现的边界

2026-10-22 的私人子任务、完成筛选模式和日报以本文及正式代码为准，下述历史 HTML 原型尚未同步这些功能。会话原型仅作交互确认，不作为运行验收证据。

维护源为 [my-work-v2.fragment.html](prototypes/my-work-v2.fragment.html)，浏览器预览为 [my-work-v2.html](prototypes/my-work-v2.html)。会话展示文件不再作为唯一维护位置。

原型尚未同步紧凑看板及移除移动按钮的布局，仍保留旧的一次性重排和无条件置顶演示，2026-10-19 新排序以本文及统一规则为准。原型覆盖分类增改删及默认设置、拖动与移动菜单、筛选、完成区间、个人任务编辑删除、项目任务权限展示、时间问候和可选文案。模拟数据以2026年10月16日为执行日期，区间也是固定示例；时间问候单独按上海时区的浏览器当前时间展示。

原型使用固定身份，不提供角色切换或真实团队管理员配置界面。根节点的 `data-team-messages` 使用 JSON 数组模拟多条标语，每次打开随机一条；空数组或只有空白项时隐藏文案行。原型只模拟本地状态，不接收其他入口的真实任务推送。

项目任务的共用新增／编辑字段规范见 [组件与交互规范](V2.0组件与交互规范.md#4-表单与详情)。新建项目任务已补齐必填日期区间与可选里程碑，执行人固定为本人；切换项目时同步更新里程碑选项。个人任务不要求项目安排字段，已有项目任务继续只读展示业务字段，仅维护执行状态和个人分类。此原型不提供负责人身份切换。

已验证模拟数据中的指针跟随、占位与边缘滚动、手动顺序、新任务置顶、一次性重排、默认分类流转、更换默认不搬动任务、分类删除保留任务，以及默认说明和文案空配置隐藏。导出后再次检查直接打开、关键交互、刷新恢复与窄屏宽度。原型通过预览环境保存模拟状态及查看偏好，刷新可能恢复；不是服务器持久化，不能跨用户协作。

未进行真实接口、数据库、权限并发、Electron 或生产验收。本轮整理落地 V2.0 设计及需求基线，未修改正式业务和数据库。原型未验证负责人代改及跨入口真实同步，不能当作生产验收。
