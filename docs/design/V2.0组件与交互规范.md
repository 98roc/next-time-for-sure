# V2.0 组件与交互规范

更新日期：2026-10-16。适用范围：V2.0 我的工作、周报与周计划、项目、团队管理。本文是设计规范，三套现有交互原型已按本规范调整；不代表正式网页、Electron 或生产已完成改造。

本规范统一展示、操作位置及交互容器。业务字段与权限仍分别以各入口设计为准，导航见 [V2.0 产品结构设计](V2.0产品结构设计.md)。旧工作区原型已清理；产品与研发需求已切换为 V2.0 开发基线，V1 仅保留迁移与验收摘要。

## 1. 容器选择

以信息量、对照需求和操作连续性为准，不要求所有按钮都打开弹窗，也不因“少弹窗”把短表单追加到页面底部。

| 场景 | 首选方式 | 保留的上下文 |
| --- | --- | --- |
| 单条任务、待建任务、里程碑、分类的新建或编辑 | 中等宽度弹窗；在详情中进入编辑时切换同一弹窗内容 | 来源记录、个人分类、项目、日期区间及未保存字段 |
| 删除、解除关联、里程碑完成、取消区间安排 | 在当前弹窗内进入确认视图；从页面发起时打开确认弹窗 | 明确对象、影响范围；返回保留编辑草稿 |
| 少量任务连续录入 | 宽弹窗，重复同一字段组，操作栏固定在底部 | 项目、默认区间；每行独立的执行人、优先级、区间、里程碑 |
| 大批量编排、长列表对照、复杂成员配置 | 优先在当前页面工作区、页签或独立宽面板中完成；不要强塞小弹窗 | 筛选、选中项、排序、滚动位置；退出前处理未保存修改 |
| 周报长文字查看、编辑、重新生成对照 | 当前页面展开文字区，原文与预览可对照 | 两个区间组合、手工文本及来源变更提醒 |
| 项目汇总进入单项目、视角切换、排序 | 页内导航或模式切换 | 当前项目、区间和查看偏好 |
| 搜索、筛选、选择人员／日期／里程碑 | 原处控件；选项较多时可用可搜索选择器 | 当前编辑内容；不另开管理弹窗 |

历史里程碑、未规划节点保留列表弹窗。进入详情、编辑、关联任务或确认时，在同一弹窗中切换，并提供“返回”。原型同一时刻只有一个遮罩与对话框，不叠加第四层窗口；返回历史不计为可见弹窗层数。正式设计一般一层完成，必要时最多三层；达到上限必须改用同层切换或页内工作区。

## 2. 操作位置与去重

### 页面、列表与卡片

- 页面级操作放在标题右侧；列表级新增、批量录入放在对应列表标题或工具栏处，不放在长列表末尾。
- 行级、卡片级操作贴近对象。标题可点击进入详情时，不再为同一行重复增加“查看”按钮。
- 同一页面、同一作用域、同一职责保留一个入口。不同项目各自的“批量新增”作用域不同，可以各保留一个；全局新增与每个日期列的新增没有必要同时常驻。
- 任务卡片的开始／完成是执行快捷操作，可以保留；详情中的状态字段用于完整维护，两者不要求机械合并。
- 低频设置可进入“更多”。菜单必须可点击和键盘访问，不依赖悬停才能操作；不可用操作保留原因和下一步说明。
- 页面导航、筛选、拖动、展开收起保留原处操作，避免无意义弹窗。已展开文字版时，页级按钮改为“收起文字版”，文字区不再放第二个收起入口。

### 弹窗与编辑面板

顶部从左到右为返回（存在上一步时）、标题和右上角的快捷关闭 `×`。底部操作组整体居中，从左到右固定为：关闭 → 删除、编辑、取消区间安排等其他操作 → 保存或确认。最左、最右均指这组按钮的位置，不将两端按钮拉到弹窗边缘；窄屏允许按此顺序换行并保持居中。确认删除位于组内最右侧并保持危险样式。

- 弹窗在当前可见视口居中，四周保留至少 12—16px 安全距离。较高弹窗限制在视口内，内容区单独滚动，标题栏和底部操作栏均保持可见，保存不需要先滚到长表单末尾。
- 关闭提供右上角有无障碍名称的 `×` 与底部最左侧“关闭”按钮，作为本轮明确保留的快捷入口例外；不额外增加同义“取消”。两个关闭入口调用同一未保存检查。返回只退回上一步；关闭退出整个弹窗流程。
- 同一操作组通常只有一个主要强调按钮。删除等危险操作使用红色文字与中性底色，和蓝色保存按钮分开；确认视图使用明确动作名，不用含糊的“确定”。
- “添加一行”在批量记录区顶部；“移除此行”在该记录标题右侧，不与删除已保存任务混淆。
- 确认删除必须展示对象名称及影响范围。解除关联、取消安排、删除任务使用不同文案，不借用同一个“删除”表达不同业务。
- 无保存动作的列表、详情只保留必要操作与关闭，不制造空操作栏。分页放在列表工具区域，不重复制造“返回”按钮。

## 3. 共用组件基线

沿用错位方块品牌和 Segoe UI、Microsoft YaHei、系统无衬线字体。浅/深色强调色为 `#5066A6` / `#A8B9EE`，选中背景 `#EEF1FA` / `#292F43`，画布 `#F5F6F9` / `#17191E`，内容表面 `#FFFFFF` / `#20232A`。正式实现集中为共享变量，不从旧鱼骨图原型复制业务结构。

| 项目 | 统一规范 |
| --- | --- |
| 颜色 | 延续雾蓝强调、浅灰画布、实色内容表面；深浅色保持相同层级。危险色只用于危险动作和错误。 |
| 按钮 | 默认高度 36px、圆角 7px，文字 13px；主按钮实色，次按钮细边框，辅助入口低强调。触屏有效目标至少 44px。 |
| 标题与表单 | 弹窗标题 18px、常规内容 14px、辅助标签 12px；字段标签在上，提示和错误靠近字段或当前操作。 |
| 间距 | 操作组间隔 8px，表单字段间距 16px，常规内容内边距 20px；记录分组圆角 10px，弹窗 12px。 |
| 宽度 | 单条表单最大 680px，批量表单最大 960px；实际宽度不能超过可用视口。 |
| 窄屏 | 双列表单变为单列，底部操作组可按关闭、其他操作、保存的顺序换行并居中；快捷关闭保留在标题行右侧。输入字号至少 16px，不缩小整个窗口来容纳内容。 |
| 空状态与禁用 | 无内容时简短解释；已有新增入口则不再放第二个。禁用操作同时说明原因，不仅改变颜色。 |
| 键盘与焦点 | 打开表单优先聚焦字段；确认视图不默认聚焦删除。Tab 限定当前对话框；Escape 返回上一步或关闭；返回尽量恢复原控件及滚动位置。 |

长表格可局部横向滚动；不让整个页面因表单溢出而横向滚动。状态始终带文字，不只依赖颜色。按钮和字段的标签、焦点轮廓在浅深色下均保留。

## 4. 表单与详情

### 任务

核心业务规则引用 [项目设计第2节](V2.0项目设计.md#2-正式项目任务)，本节只统一展示。

1. 项目、创建人作为上下文展示，创建人只读。
2. 任务名称独占一行；执行人与优先级同组；完整日期区间独占一行；关联里程碑及执行状态随后展示。
3. 批量新增重复相同核心字段，每行可单独选里程碑、执行人、优先级和日期区间。新任务状态默认未开始。
4. 周计划在核心字段后增加“该区间预计天数”，不把它当作任务总工期；当前安排区间的修改不静默覆盖任务在其他区间的安排，目标区间已存在时提示用户直接编辑已有安排。
5. 我的工作区分个人与项目任务。个人任务不展示无意义的项目执行人、里程碑和强制区间；创建项目任务时默认由本人执行，必须选择日期区间，里程碑选填。
6. 项目任务的普通执行人详情显示相同业务信息，但业务字段只读；个人分类与执行状态可维护。有管理权限者的完整编辑表单遵循同一字段规范，不以入口扩大权限。

原型中“项目”固定模拟项目研发负责人，“周报与周计划”固定模拟团队负责人，“我的工作”固定模拟普通执行人。统一的是展示与交互契约，不是跨原型共享模拟数据，也不代表真实权限鉴权。

### 里程碑

- 详情展示项目、状态、预计完成日期与关联任务，底部操作组居中，依次为关闭、编辑、标记完成；未完成任务数量作为不可完成的原因。
- 编辑在同一弹窗中展示目标名称、预计完成日期。日期为空归入未规划节点；保存后回到原详情或列表。
- 日期列只展示日期、数量与节点，不再每列重复新增；项目规划标题区保留唯一“新增里程碑”。历史表通过名称打开详情，不再重复“查看”。
- 从详情打开关联任务后可返回；解除关联使用明确确认，保留任务。完成条件仍以 [项目设计第4节](V2.0项目设计.md#4-里程碑) 为准。
- 任何本项目研发负责人可确认或重开；完成后关联任务回退保持完成并提示核验，新增未完成关联前先重开。权限与状态规则引用项目设计，不按原型固定身份推断。

### 分类、日期与团队配置

| 对象 | 展示与入口 |
| --- | --- |
| 分类 | 新增在我的工作顶部；改名、设为默认、删除在分类标题菜单；删除表单清楚说明任务接收分类与默认继承。 |
| 团队日期区间 | 日期区间入口位于周报页标题区；开始、结束成组排列，保存位于底部居中操作组的最右侧。 |
| 成员账号 | 成员表顶部保留新增入口，创建账号／添加已有账号在同一入口下选择；重置密码、启停放对应成员操作区，不在页底另设按钮。 |
| 项目基础配置 | 项目表顶部新增，行内编辑／管理成员／进入项目各承担不同职责；表单两种负责人均支持多人选择。 |
| 项目成员 | 少量配置可使用宽弹窗；复杂名单与阻塞项需持续对照时可用当前页面工作区。移出不满足条件时在当前面板列出任务、里程碑与角色原因，不叠加多层提示。 |
| 团队文案 | 团队管理顶部设置入口维护纯文本，短表单使用弹窗；不占用我的工作看板操作区。 |

团队管理本轮仍只有设计文档，上表作为后续实现规范，不声称已新增团队管理原型。账号维护和成员移出限制遵循 [团队管理设计](V2.0团队管理设计.md)。

## 5. 保存、返回与反馈

- 表单内容有变化时，关闭、Escape 或返回显示当前表面内的“继续编辑／放弃修改”，不再叠加确认弹窗；取消删除回到原编辑草稿。
- 保存校验失败时保留所有输入；保存成功后返回对应详情／列表并刷新可见内容。正式实现需在请求失败时保留草稿并显示重试信息，提交中禁用重复提交，不能以原型内存写入代替并发设计。
- 弹窗遮罩不作为误触关闭入口。背景不可交互，避免操作落到被遮挡页面。
- 页内文字版保留既有草稿和重新生成对照。重新生成入口只在文字区头部出现一次；未同步提示负责解释状态与提供核对操作，不再重复放一个同职责按钮。
- 项目与任务的查看上下文在返回时保留；保存造成当前记录不再符合筛选时，应给出离开列表的原因，不能把保存成功误认为记录丢失。

## 6. 本轮交付与检查

三套原型使用共用样式与对话框控制器。浏览器导出预览固定 iframe 为可见视口高度，页面在容器内滚动，避免长页面将弹窗居中点推到屏幕下方；维护与导出方式见 [原型 README](prototypes/README.md)。本次修改不触及正式应用或数据库。

| 范围 | 本轮调整 |
| --- | --- |
| 项目 | 任务、待建任务、批量、里程碑、历史及未规划节点的操作栏统一；去重日期新增与历史查看；同层返回与未保存保护。 |
| 我的工作 | 任务和分类操作统一；项目任务创建补齐日期区间与里程碑；保留个人任务和普通执行人只读边界。 |
| 周报与周计划 | 安排入口移至列表上方；任务与批量补齐共用字段；取消安排加明确确认；文字版保留页内阅读对照并去重按钮。 |
| 团队管理 | 将按钮布局、容器选择、成员配置展示约束纳入设计文档；没有可运行团队管理原型。 |

最后一个区间安排已确认禁止直接取消，允许改排到其他区间；原型已有禁用提示，正式实现仍须服务端校验。选择已有任务后新加入区间的预计天数仍留空。

先前组件统一时已通过浏览器检查项目原型的里程碑详情、编辑、未保存关闭提示、继续编辑、保存返回及关联任务表单；已查看深色实际布局。后续浏览器工具因 Work 设置禁用而中断，最终焦点、样式与返回刷新修订，以及其余两套原型、窄屏／浅色实际检查尚未完成。本次文档整理没有补充这些浏览器证据。

最终静态检查通过：项目指定 Node 24.21.0 下的全部脚本语法、未定义标识符／不可达语句／重复对象键检查，三套原型的重复生成逐字节一致，V2.0 设计文档链接目标存在。未运行正式应用构建和业务测试，因为本次仅修改设计及模拟原型；这些静态结果不替代浏览器交互、真实 API、数据库、Electron 或生产验收。
