# V2.0 项目设计

确认日期：2026年10月16日；投入与完成结果更新于2026年10月22日；里程碑分区布局更新于2026年10月23日。本文维护已确认规则；当前实现、验收与上线状态见[实施记录](../development/V2.0实施记录.md)。

本文维护“项目”入口的规则及布局。入口职责见 [V2.0 产品结构设计](V2.0产品结构设计.md)，[浏览器原型](prototypes/project-v2.html)用于体验交互，[维护说明](prototypes/README.md)说明源码及导出方式。本文是 V2.0 详细业务规则，与[产品需求](../product/需求说明书.md)及[研发需求](../product/研发需求说明书.md)共同构成开发基线，不表示线上行为已经改变。

## 1. 入口与页面结构

项目入口分为项目汇总和单个项目两层，沿用留白、雾蓝强调和现有导航风格。

- 项目汇总按项目分块，展示本人有权查看的项目在所选日期区间内的任务执行情况及待建任务；普通成员可查看参与项目，团队负责人可查看本团队项目；状态数量作为辅助信息，不以统计卡片替代任务列表。
- 汇总卡片标题用加大加粗的项目名称、雾蓝短竖线和轻底色突出分组；名称后同排展示“区间任务 N · 未开始 N · 进行中 N · 已完成 N”，窄屏自然换行。区间总数不再单独占一行，任务恢复排序菜单移至卡片标题右侧，仍只作用于本项目正式任务列表。
- 采用“并排概览”：任务在左、待建任务在右，两类列表直接展示；没有待建任务时，任务表占满整行，不保留空白区域。窄屏依次排列。
- 汇总以查看为主，点击项目进入维护页面，点击任务或待建任务打开共用弹窗。
- 单个项目保留“任务”“里程碑”“待建任务”三个页签。原“任务看板”改称“任务”，以表格为主，支持批量录入。
- 汇总页提供“里程碑总览”，按项目汇总同一批里程碑，不创建新的里程碑类型或副本。
- 单条新增、编辑、转换、删除确认使用弹窗；信息量大的编排允许在当前页面工作区完成。容器、顶部标题与底部操作栏和去重规则统一见 [组件与交互规范](V2.0组件与交互规范.md)。

## 2. 正式项目任务

### 字段与安排

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，不设置独立的任务说明或检查清单。 |
| 执行人 | 必填且只能一人；多人工作拆成多条任务。 |
| 日期区间 | 创建正式任务时必须指定，使用团队维护的区间，展示完整起止日期。 |
| 优先级 | 1 最高、2 高、3 中、4 低、5 最低，默认 3 中。 |
| 执行状态 | 未开始、进行中、已完成，允许相互回退。 |
| 关联里程碑 | 可选，一条任务最多关联一个本项目里程碑。 |
| 创建人 | 系统记录，不能修改；不因创建任务而自动获得任务维护权限。 |

所有入口直接创建正式任务，以及待建任务转换，都必须明确执行人和日期区间。暂时不能明确安排的事项先放待建任务。本规则替代早期“正式任务允许待分配、未排期”的讨论。

项目、我的工作和周计划引用同一条任务。成员自行创建时默认由本人执行；负责人可以直接分配给项目成员，保存即生效，不设发布流程。跨区间延续使用原任务，保留原区间安排，具体编排见 [周报与周计划设计](V2.0周报与周计划设计.md)。

单项目的任务表默认展示全部未完成任务，包含未来安排和原安排区间已结束但尚未完成的任务；支持按日期区间筛选，已完成任务按需查看。默认规则和各入口隔离见[统一排序规则](../product/研发需求说明书.md#统一默认排序与手动排序)。项目汇总卡片、区间任务、项目内任务表及待建列表提供拖拽把手，支持上下方向键；保存失败明确反馈，不改变任务归属、执行人和日期安排。项目页的任务顺序在汇总和详情之间共用，日期与状态筛选只投影该顺序。

项目汇总提供“项目排序／完成排序”模式：收起任务内容后显示紧凑项目行，整行可拖动，完成后恢复原汇总。项目恢复排序放在排序模式工具栏的“⋯”；正式任务、待建列表的恢复入口收进各自标题或工具栏右侧“⋯”，菜单注明完整作用范围。项目名称和状态汇总优先同排，低频操作不独占一行。外层项目和内部任务共用稳定落点、平滑让位及边缘滚动交互，保存失败撤回预览并提示。

### 人员属性与权限

任务人员字段为创建人和执行人，不另设任务负责人或提出人。团队负责人、项目研发负责人、项目经理是角色，不是任务上的额外人员字段。项目角色配置及多人兼任见 [团队管理设计](V2.0团队管理设计.md)。

| 操作 | 权限 |
| --- | --- |
| 修改任务名称、执行人、日期区间、优先级及里程碑 | 团队负责人、项目研发负责人在管理范围内维护。 |
| 负责人代改执行状态 | 团队负责人、项目研发负责人可在管理范围内替执行人开始、完成或回退，记录实际操作者。 |
| 执行人维护任务 | 可修改执行状态、已有周期预计投入、累计实际投入和 AI 贡献率；自行创建可填写完整创建信息，保存后不能改名称、人员、排期、优先级或里程碑。 |
| 删除正式任务 | 团队负责人、项目研发负责人可以删除管理范围内的任务。创建人也可以删除自己创建且当前为“未开始”的任务。 |
| 状态回退后删除 | 只看当前状态，不检查是否曾经开始；改回“未开始”后，创建人恢复上述删除条件。 |
| 兼任多个角色 | 按所具备的角色权限操作；不能把执行人限制误用于有管理权限的负责人。 |

个人分类和顺序属于个人视图，不作为任务业务字段修改，见 [我的工作设计](V2.0我的工作设计.md)。私人任务不适用本节的项目任务约束。

### 投入与完成结果

以下规则于 2026-10-22 确认：

- 预计投入属于具体周期安排，选填；空表示未估算，明确填写 0 表示零投入。至少保留一条安排，日期必填。新建默认一条：入口带入的周期优先，否则使用本周期；打开已有任务不自动追加或更换安排。
- 追加周期保留原安排和预计值，新周期预计留空；改排到其他周期时预计留空，可重新估算。不同周期日期和预计始终成对展示，不把合计称作最初预算。
- 累计实际投入属于整条项目任务，允许 0，最多两位小数，范围 0—9999.99 人天；按 8 小时为 1 人天理解。预计投入采用相同数值范围及精度。实际投入不是完成周期的单周实际工作量。
- AI 贡献率为成果贡献程度的人工分档：无=0%；低=大于0%且小于30%；中=30%至60%（含两端）；高=大于60%且不超过100%。不自动折算为节省人天、超支率或效率。
- 完成结果在创建表单和未完成任务详情中隐藏，仅详情当前选择“已完成”时展示；保存为完成时累计实际投入和 AI 贡献率必填，首次未填写 AI 时默认高，已有值保留。重新打开后隐藏字段，不清空已保存结果。
- 执行人、团队负责人、项目研发负责人可在各自权限范围修改上述三个投入字段；仅查看者不能修改。预计值编辑不授予增删、改排周期的权限。
- 所有完成入口共用规则，包括按钮、拖入完成分类、详情修改状态/分类、负责人代完成、Agent。新建项目任务可选完成分类，保存时另行填写完成结果，确认后一次性创建；取消返回创建草稿。私人任务创建保留个人分类，可直接完成，不增加预计、实际或 AI 字段。
- 重开保留已有结果；再次完成确认累计总数，不重复相加。结果修改保留实际操作者及版本历史，不覆盖此前快照。
- 旧已完成任务不自动补零或默认高，显示未填写。修改无关字段不强制补齐；编辑完成结果或重开后再完成时执行必填规则。
- 本次只维护任务详情、完成填报及历史，不新增周工时填报、计时器、统计看板或自动效率计算。

## 3. 待建任务

- 待建任务用于收集尚未明确安排的项目事项，只填写名称和优先级；系统另行记录创建人。
- 项目经理、项目研发负责人、项目成员都可以提出事项；团队负责人按管理权限统筹。
- 创建人可以修改、删除自己提出的待建任务；团队负责人、项目研发负责人可以维护管理范围内的全部待建任务。
- 团队负责人、项目研发负责人可转换并安排给项目成员；普通项目成员可转换并由本人执行。仅具备项目经理角色时只能提出待建任务，兼任其他角色时按相应权限操作。
- 转换弹窗继承名称和优先级，必须填写执行人和日期区间，里程碑可选。保存后从待建列表移出，成为正式任务。
- 正式任务的创建人保留为待建任务原创建人，转换操作人另作操作记录，不新增独立“提出人”字段。
- 不引入需求审批、补充、暂缓或任务领取流程。

## 4. 里程碑

### 维护、关联与完成

- 团队负责人、项目研发负责人维护里程碑，其他项目参与者查看。
- 里程碑维护阶段目标名称和预计完成日期；没有日期时放入“未规划里程碑”，不因此创建任务。
- 一个里程碑可以关联多条任务，任务也可以不关联里程碑。任务创建、编辑、批量新增时均可选择里程碑。
- 关联里程碑下拉框固定以“不关联里程碑”开头，新增关联仅提供本项目未完成目标。有预计完成日期的按日期升序，同日按创建时间升序；未规划目标置于最后，也按创建时间升序，同一创建时刻按标识稳定排序。编辑已有任务时保留其原关联的已完成目标并标注“已完成”，其他已完成目标不提供选择；切换草稿选项不清除原关联候选。此规则只作用于共用关联下拉框，不调整里程碑看板及保存、解除关联确认流程。
- 详情弹窗列出关联任务，团队负责人、项目研发负责人可以直接“解除关联”。该操作只清除关联关系，保留任务及执行人、日期区间和状态，不删除任务。
- 任意本项目研发负责人都可手动标记里程碑完成，不限于某一指定责任人。没有关联任务，或关联任务全部完成时允许操作；还有未完成任务时按钮不可用，并说明未完成数量。满足条件不会自动完成里程碑。
- 里程碑责任归属用于成员移出检查，不构成专属确认权限；重开也由任意本项目研发负责人操作。团队负责人仅凭团队角色可维护目标，不自动取得此处研发负责人的完成/重开权限，兼任时按角色合并。
- 里程碑完成后关联任务回退，保留里程碑已完成状态并提示负责人核验，不自动重开；负责人判断阶段目标未达成时手动重开并保留历史。新增未完成关联任务前必须先重开，创建、批量新增和编辑关联均执行同一检查。
- 卡片和详情均可发起标记完成，操作前确认阶段目标已达成。展示任务完成数量，不计算里程碑百分比。

### 页面布局

近期里程碑按日期从左到右分列：日期在上、卡片在下，同日多个目标在同一列纵向排列。宽屏每行最多 4 个日期列，超出自动换行；按内容区域宽度收窄为 2 列、1 列，不再横向滚动或提供方向按钮。项目规划标题数量仅统计当前及后续日期的目标。

历史判断基于当天所在自然周的周一，早于该周一的预计完成日期归入历史，与页面任务筛选区间无关：

- 主页面不展示历史节点，也不下拉展开历史表格。点击“历史里程碑”打开弹窗。
- 入口提示明确截止日期、历史数量及未完成数量，避免隐藏尚未完成的旧目标。
- 弹窗采用日期倒序表格，列出名称、预计完成日期、状态、关联任务完成数和查看操作，每页 10 条。
- 查看历史目标后可按同样规则维护；修改日期后重新归入对应日期区域。归入历史本身不改变任何业务状态或任务关系。
- 单项目和“里程碑总览”采用同样规则；总览按项目展示，各项目的历史入口查询对应项目。

无日期的目标统一称为“未规划里程碑”，在项目规划下方独立分区，与上方等宽，标题展示数量、视觉弱于日期规划。默认展开，支持收起；宽屏每行最多 3 张卡片，超出自动换行，窄屏依次收为 2 列、1 列；无数据时显示简短空状态。移除右上角未规划列表弹窗入口，复用现有卡片、详情、编辑保存及完成确认弹窗。填入日期并保存后进入对应近期日期列或历史列表，不新增页面底部的迁移提示或操作说明；既有共用保存反馈与错误提示保持原样。

## 5. 共用表单与跨入口关系

任务编辑、批量新增和待建任务转换共用核心字段及弹窗结构。编辑展示单条记录，批量新增重复同一字段组，每条均可独立关联里程碑。入口只提供默认值和权限差异，不各自维护不同的任务字段含义。

跨入口共用表单约定维护在 [组件与交互规范](V2.0组件与交互规范.md#4-表单与详情)。各入口均支持周期预计投入，按字段权限展示；原型之间不共享数据，旧原型尚未包含本节的投入及完成结果规则。

## 6. 区间关系与实现边界

以下规则已于 2026-10-16 确认；原型未覆盖的部分须按文档实现：

- 项目汇总包含该区间安排及实际执行的任务，按任务去重；实际执行与历史状态口径统一遵循[周报与周计划设计](V2.0周报与周计划设计.md#3-项目与人员视角)。原型仅按安排筛选，不代表最终统计口径。
- 正式任务至少保留一个日期区间安排，不能直接取消最后一个；可原子改排到其他区间。存在其他安排时可取消指定区间，不自动退回待建任务。
- 多人确认权限与完成后变更按第4节执行；责任归属及旧数据字段映射须在迁移设计中落到具体契约。固定模拟身份不能证明多人权限已验收。
- 已完成里程碑的重开、核验提示和新增关联检查需要补齐正式实现；不能只保留点击完成时的一次检查。
- 并发、状态事件、删除审计遵循[研发需求](../product/研发需求说明书.md)，旧模型映射见[迁移准备](../development/V2.0迁移与研发准备.md)；原型删除数组记录不代表数据库物理删除策略。

## 7. 原型交付与验证边界

维护源为 [project-v2.fragment.html](prototypes/project-v2.fragment.html)，浏览器预览为 [project-v2.html](prototypes/project-v2.html)。仓库源是后续维护位置，会话预览为展示副本。初始直接展示单项目里程碑，点击“项目汇总”可查看完整入口。

原型覆盖项目并排汇总与空待建区扩展、任务表及筛选、共用任务弹窗、批量新增并关联里程碑、待建转换、删除确认、里程碑总览、日期列横向滚动、历史弹窗分页、未规划节点弹窗、关联解除及完成条件。权限说明以本设计为准，原型使用固定项目研发负责人身份，不提供真实角色鉴权。

上述旧 HTML 原型尚未同步 2026年10月23日确认的里程碑分区及自动换行布局，布局以本节规则和当前前端实现为准，不以旧原型覆盖已确认规则。

示例日期固定为 2026年10月16日，因此 2026年10月11日及以前为历史。正式实现应取团队时区的当天日期。模拟业务数据刷新后恢复，部分查看偏好可由预览环境记住；不写入业务系统，不跨原型共享数据。

已做浏览器模拟交互与窄屏检查，包括弹窗保存、取消及键盘操作、批量里程碑、转换保留创建人、空待建区、历史日期边界及分页、完成条件、解除关联保留任务字段，以及仓库导出预览打开。未实施真实 API、数据库、Electron 或生产验证，不代表上述正式业务已开发完成。
