## V2.0 共用表单约定

统一规则维护在 [V2.0 组件与交互规范](../V2.0组件与交互规范.md)，不在各入口重复定义。三套原型已统一顶部标题与底部操作栏、同层弹窗切换、未保存保护和任务核心字段；我的工作保留普通执行人的只读边界，周计划扩展区间预计天数。长文字继续页内编辑对照，团队管理只有设计文档。

- [v2-components.css](v2-components.css)：共用颜色、按钮、表单、弹窗及窄屏样式。
- [v2-components.js](v2-components.js)：原生对话框、底部操作、返回栈、草稿与焦点保护；同一时刻只显示一个遮罩。
- [build-v2.py](build-v2.py)：将共用组件内联到三份维护源的 `BEGIN V2 SHARED` / `END V2 SHARED` 区域，再调用 visualize 渲染器生成浏览器预览，并固定预览容器为浏览器可见高度，避免长页面造成弹窗偏下。生成区域不可手工修改。

CSS/JS 内联使各导出页面仍可单独打开，无需启动后端或使用本地脚本网络请求。三套原型共享组件契约，但模拟任务相互独立。

## 重新生成浏览器预览

V2.0 使用以下命令同步三个入口，避免共用组件版本不一致：

```powershell
python docs/design/prototypes/build-v2.py
```

默认使用下方 visualize 版本；安装路径不同可传 `--renderer '完整路径/scripts/render.py'`。脚本兼容 PowerShell 5.1 调用，依赖 Python 及本机 visualize 渲染器。重复执行结果应一致。

使用 Codex visualize 技能附带的 `scripts/render.py`，无须启动项目服务。PowerShell 5.1 示例（按本机安装位置设置 `$visualizeSkill`）：

```powershell
$visualizeSkill = Join-Path $env:USERPROFILE '.codex/plugins/cache/openai-bundled/visualize/1.0.50/skills/visualize'
python (Join-Path $visualizeSkill 'scripts/render.py') `
  (Join-Path $PWD 'docs/design/prototypes/weekly-v2.fragment.html') `
  (Join-Path $PWD 'docs/design/prototypes/weekly-v2.html') `
  --title '下次一定 · V2.0 周报与周计划' --force
```

渲染器属于本机技能依赖，未复制到仓库；技能升级后应核对实际路径。重新生成“我的工作”时，将文件名替换为 `my-work-v2.fragment.html` 和 `my-work-v2.html`，标题替换为“下次一定 · V2.0 我的工作”；重新生成“项目”时使用 `project-v2.fragment.html`、`project-v2.html` 和标题“下次一定 · V2.0 项目”。三套 V2.0 原型统一优先使用 build-v2.py；单独调用渲染器不会同步共用组件或执行额外导出修正。

## 我的工作示例配置

`my-work-v2.fragment.html` 根节点的 `data-team-message` 模拟管理员配置的团队文案。设置为 `data-team-message=""`、只有空白或删除该属性，重新导出后文案行隐藏，时间问候保留。配置规则统一见 [团队管理设计：团队文案](../V2.0团队管理设计.md#5-团队文案)，这里不提供真实管理员配置界面。

该原型通过预览环境保存模拟任务、分类、排序及查看偏好，刷新可能恢复；浏览器独立预览保存到本机预览存储，不是业务数据，也不保证所有浏览器的 `file://` 存储行为一致。日期区间和任务完成使用固定演示日期，问候按上海时区的浏览器当前时间展示。

## 使用与验证边界

- 周报与周计划的任务、手工文字、日期修改和排序刷新恢复模拟初始数据，查看偏好可能被预览环境记住；我的工作模拟状态的恢复范围见上节。各原型均不写入业务系统。
- 图标及部分预览资源来自公共 CDN，完整外观需要网络；源文件没有业务网络请求。
- 浏览器或系统限制剪贴板时，复制降级为选中文字并提示快捷键。
- 原型不提供真实权限、持久化、并发或生产保证。检查记录与待研发边界见对应设计文档。
- V2.0 的“项目排序”按钮会收起任务内容，支持抓住项目整行排序；“完成排序”返回原来的左右任务布局。

## 已确认但尚未完整模拟的规则

2026-10-16 已确认的业务以设计文档为准；本次整理不修改原型业务脚本。正式研发不能因下列简化而遗漏规则：

- 项目汇总及周报包含实际执行；已结束区间显示结束时状态，不能用当前状态代替。
- 已结束日期区间锁定，当前及未来调整须展示影响并保持连续、不重叠。
- 负责人可代改项目任务状态并记录操作者；普通成员可见参与项目全部任务和安排。
- 任意项目研发负责人可确认或重开里程碑；任务回退后保留完成并提示核验，新增未完成关联前先重开。
- 周计划排序团队共享；文字稿由团队负责人维护，其他人仅生成本人有权范围文字，多人修改检测冲突。
- 最后一个安排禁止直接取消，可改排；原型已有禁用提示，但不能替代服务端事务校验。

原型中的检查记录是之前的模拟验收，本次文档整理未重新执行浏览器交互或生产验证。
