## 来源映射决定

- 保留 accounts、teams、projects、project_members 业务身份，项目负责人支持多人。保留身份审计及会话/Token 安全能力；不重建真实账号。
- team_tasks 与有效 task_assignments 按执行人转换；有对应 personal_items 的名称、状态和个人位置一并保留。同一来源可能映射多个 v2_tasks，写入 v2_migration_map。退出、转交不能伪造完成。
- 没有执行人的任务转 v2_backlog。未接收 work_requests 转待建；已接收来源不得再创建重复事项。原创建人优先从创建事件还原，证据缺失列异常，不用主负责人猜测创建人。
- 私人事项仍为 private，仅本人可见。kind=work 的独立个人工作为项目任务，不改为私人任务。生产当时 17 条个人事项全部为 work。
- 2026-10-16 用户明确批准：8 条有执行人但无区间的工作补入 **2026-10-12—18**，保留执行人和状态；安排来源标为 `migration_supplement`，不伪造提前安排。具体旧 ID 留在本地盘点报告；这项授权不扩大到以后新增的其他异常记录。
- 原 weekly_arrangements 保留每区间预计天数，跨区间不复制任务；一对多拆分无法可靠分摊时不能将原投入重复到每条任务。需输出异常后决定。
- 旧安排缺失加入时刻且事件无法还原时用 `migration_unknown`，计划性显示未知。真实已知事件按时间还原，缺少历史时标明不可还原。
- project_milestones 保留责任、日期、状态和拆分后的任务关系；完成权限按项目研发负责人角色判断。
- 周报草稿及发布快照先提取人工内容和来源，再删除发布专属数据；合并时保留内容、顺序和版本来源。转换已实现：人工修改草稿及发布快照文字进入受保护的共享文字稿，发布顺序进入共享排序；复杂多版本或无法确定的内容拒绝自动转换，不能先删源表。
