# V2.0 迁移与研发准备

确认日期：2026-10-16。状态：迁移原则已确认；逐表映射、迁移脚本及演练尚未完成。本文不代表已经执行数据库或业务代码改造。

## 1. 环境边界

- 本地开发数据库允许删除后按 V2.0 重建。执行前仍须核对连接目标确为本项目开发库，不能因数据库同名而误操作生产。
- 生产环境完整迁移到 V2.0：保留功能的已有数据尽量完整保留；已取消功能独有的数据删除，不建立旧业务长期只读入口。
- 生产执行前停止写入、完整备份并验证可恢复；迁移完成后以 API 和数据库回读核对。备份是恢复材料，不是对外保留被取消功能。
- 已执行的 V1 迁移文件及初始化 SQL 保留为版本历史；新增 V2.0 迁移，不篡改历史迁移，不把清空开发库的方式用于生产。
- 本次执行范围是落地、整理文档及 Git 提交推送；本轮不执行删库、生产迁移或部署。

## 2. 功能与数据对应

目标范围以[产品需求](../product/需求说明书.md)为准。“删除功能数据”按数据含义和依赖判断，不能见到旧模块表名就整表删除。

| V1 数据 | V2.0 处理原则 | 必须核对 |
| --- | --- | --- |
| 账号、团队、项目、成员、项目角色 | 保留身份和有效关系，适配多人项目经理、研发负责人。 | 账号不能重复创建；角色不丢失、不扩大权限；已停用状态保留。 |
| 团队任务、分工、关联个人工作 | 转换为单执行人项目任务；多个入口引用同一记录。 | 不能简单取第一名执行人或丢弃其他人的工作；一人多个个人事项不能无条件合并丢失名称与状态。 |
| 待分配、未排期任务及尚未接收需求 | 可保留的名称、优先级、创建人映射为待建任务；正式任务需满足必填条件。 | 已接收需求的正式任务不能重复迁移；旧审批状态、补充流程不进入 V2.0。 |
| 个人任务、分类、个人排序 | 私人任务保留隐私；工作事项归入项目任务转换；分类适配状态及唯一默认分类。 | 不把工作事项错误变成私人事项；保留可用顺序，重名与缺省分类有确定处理。 |
| 独立里程碑、任务关联 | 保留目标、日期、状态、可保留的责任及任务关系。 | 一对多拆任务后仍对应正确里程碑；已完成但含未完成关联的旧记录列为异常，不能自动伪造完成或重开。 |
| 周安排、预计投入、周报文字 | 转为日期区间安排、区间投入和共享文字稿。 | 同一任务跨区间不复制；每区间天数单独保留；旧周报组合、来源和人工文字须形成明确映射。 |
| 旧计划及周报发布版本 | 发布流程与版本浏览功能取消；可用于新安排、人工文字及历史总结的内容先提取，旧发布机制专属数据再删除。 | 逐版本核对，不能先删快照再迁移文字；多份文字如何合并、哪些版本仅留备份须在映射清单说明。 |
| 状态事件及有效历史 | 保留用于历史总结、操作者审计和已保留对象追溯的事实。 | 状态回退不能覆盖旧完成记录；只在现存证据足够时还原历史，缺失标注不可还原，不补造时间。 |
| 小组、组长、分工机制专属数据、审批过程、检查清单、说明、独立进展、累计百分比、人工标签、阻塞依赖、通知、归档交接专属数据 | 先完成保留对象及必要历史提取，再删除取消功能独有数据。 | 分工中执行人和状态仍是迁移来源；不能连带删除项目、任务或基础审计。归档项目仍有保留数据时需显式映射，不能默认全删。 |

私人任务转项目只在设计中提出方向，字段、历史与权限未闭合；不借本次迁移创建一个未经定义的新操作。相关边界见[我的工作设计](../design/V2.0我的工作设计.md)。

## 3. 编码前的技术交付

1. 对当前代码、数据库结构及生产只读数据做清点，输出每类数据的保留数量、转换数量、删除数量和异常清单。生产清点时重新确认环境，不使用旧快照代替当前事实。
2. 定义旧 ID 到新 ID 的映射，重点处理多人任务、父子任务、多个关联个人事项、无执行人或无区间、取消任务、归档项目、历史负责人已离开及旧周报多版本。自动映射不可靠的记录单列具体建议，不能静默删改。
3. 明确历史状态、执行人变更、区间安排及临时插入的事件模型；用它实现区间结束时的总结与计划外识别，不直接读取当前状态充当历史。
4. 明确共享排序、共享文字、日期调整、任务改排、角色变更的事务及版本冲突。已结束区间锁定的是日期边界；任务后续状态变化仍合法，不能据此修改历史状态。
5. 列出页面、Controller、契约、MCP 工具、Skill、通知轮询、定时/读取副作用、测试和数据库的删除或替换清单，禁止仅隐藏页面而让旧接口继续写入取消功能。
6. 在隔离数据库演练“备份→迁移→回读→恢复”，记录 MySQL DDL 部分失败的恢复办法，再执行正式迁移。

这不是要求重新确认已经定下的产品规则；只有无法无损映射的具体生产数据例外需要单独处理。

## 4. 迁移与业务验收

- 对账账号、项目、私人任务、有效项目工作、里程碑、区间安排及手工文字；保存旧新标识对照，允许因多人拆分导致新任务数增加，但须说明每条来源。
- 核对唯一关联、引用完整性、重复执行结果、状态事件、权限、实际中文 COMMENT；私人内容不得进入团队总结。
- 验证普通成员查看参与项目全部任务与安排；负责人代改状态留下操作者；其他项目越权拒绝。
- 验证最后区间不能取消、改排原子性；完成里程碑遇任务回退保留完成并提示核验，新增未完成关联先重开。
- 验证历史区间日期锁定、当前及未来边界调整影响预览、区间统计与文字变更提醒。
- 验证两个真实用户并发修改排序、文字及任务，冲突不得覆盖已保存内容；网页、Electron、Agent 分别记录证据。
- 发布后关闭旧入口和写接口；失败恢复必须覆盖应用与数据，不能只回退应用宣称恢复完成。

V1 历史结构和证据摘要见[压缩基线](../archive/v1/README.md)，现有部署机制及限制见[Docker 部署](Docker部署.md)。现有脚本尚不具备上述 V2.0 转换与恢复演练能力。
