# 任务与个人执行使用说明

## 误开始与紧凑看板

团队任务卡片支持直接拖拽排序；右上角“⋯”保留上移、移至列末等键盘与触屏备用入口。卡片只展示标题、紧凑负责人/日期、必要状态及常用动作，详细内容点击标题查看。

任务主负责人、项目研发负责人和团队负责人可从卡片“⋯ → 删除任务”直接打开影响确认弹窗，不再填写删除原因；确认成功后关闭弹窗并刷新列表。误开始已撤销且没有其他执行事实时允许删除；实际执行历史、正式发布引用或关联事项等阻止原因仍会显示并阻止删除。个人事项删除同样无需填写原因。

## 入口与工作流程

新建任务先选择关联里程碑（选填），再填写名称。选择里程碑会在名称为空或仍为自动带入值时填入目标名称；名称可自由修改，手动修改后切换或取消关联不会覆盖。关闭后重新打开使用空白表单。2026-10-15 已通过类型检查、ESLint及浏览器验证字段顺序、自动带入、切换、手动保护与关闭重置；未提交测试任务。[表单截图](evidence/ux/task-create-milestone-title.png)。

1. 团队负责人可以直接从“项目”（`/work`）创建项目，成功后进入新项目并引导添加任务；无项目的成员会看到加入项目的提示。已有项目可切换“需求”视图，由项目经理提交需求，项目研发负责人或团队负责人处理。接收时指定主负责人，生成一个任务；不会自动分配人员。
2. 新建任务的主按钮为“创建并分配人员”，保存后自动进入详情的人员分工；“仅创建”允许暂不分配。组长／团队负责人可多选成员，在同一行选择负责小组和填写工作内容，也可点击“我来做”选中符合条件的本人。整批保存成功后进入“周安排”，选择本周、下周或其他周，再一键将勾选分工加入草稿，目标和投入可稍后补充。普通成员只可认领本人工作；负责小组可选“团队直属”，无需先入组，交由团队负责人统筹。
3. 成员可以直接在分工上开始、记录进展和完成，也可用“带入个人空间”建立关联事项。个人空间支持独立工作（必须选项目）与私人事项（仅本人可见）。
4. 分工完成前显示尚未完成的个人工作，确认后停止关联执行但保留个人状态、时间。主负责人整体结束任务同样需要确认影响范围，不会替成员完成。

## 看板、进展与时间

- 待分配卡片右下角突出“分配人员”，开始为弱化的次要动作；已有分工时突出开始。任务详情顶部直接提供“编辑任务内容”，主负责人旁提供“更换”：团队负责人、项目研发负责人可就地选择当前项目可用研发成员，保存成功后收起编辑并刷新任务；更换不改动已有人员分工。人员分工、周安排、进度与执行、更多分区展示。已保存步骤可以关闭后继续；周中调整入口见[周计划使用说明](周计划与周报使用说明.md#周计划)。
- 添加执行人时，符合条件且尚无有效分工的主负责人默认勾选、置顶，可取消；切换步骤或刷新候选不会覆盖手工取消，点击保存才创建分工。未加入小组的团队成员默认使用“团队直属”，团队负责人可直接勾选；有小组的成员默认带入小组，也可改为直属。组长只能分配本组人员。已有有效分工的人不重复出现在新增候选中。
- 团队看板固定待开始、进行中、已完成三列。拖动和按钮执行同一业务操作；进行中拖回待开始时执行上述撤销开始检查。已取消任务通过筛选查看。
- 上移、移至列末及拖到另一卡片前均保存顺序。保存成功后位置改变；冲突时保留原位置，刷新核对后重新操作。
- “我的事项／全部可见工作”使用紧凑页签切换，刷新位于右侧；无项目、无事项时隐藏该栏并展示下一步引导。全部可见工作仍包含本人事项与当前有权查看的团队工作，不扩大权限。
- 个人分类和排序独立于状态。分类窗口按行编辑名称、保存，移除前确认事项去向。空分类可接收拖动；卡片可直接拖动，手机可横向滑动看板，或使用详情“更多设置 → 分类与排序”表单。移除分类只将事项放回未分类。
- 个人卡片按状态突出下一步：待开始显示“开始”，进行中显示“记录进展”，完成为次要动作；标题进入“事项内容”，右上角“···”进入“更多设置”。详情分为事项内容、进展记录、更多设置，点击“编辑内容”修改名称、说明和检查清单；分类、关联、时间修正、标签及历史在更多设置中。内容保存成功退出编辑，进展保存成功清空已提交内容，失败保留输入。
- 点击个人卡片“记录进展”直接进入进展分区。进展逐条记录发生日期、归属周（周一）及内容。个人及分工进展表单可选择周内任意日期作为归属周，系统转为周一，默认填写今天及本周。本人可补记实际时间，主负责人可修正团队整体时间；这些操作不传播到其他对象。
- 检查清单完成不自动完成事项；累计进度100%不自动结束团队任务。个人事项可在“更多设置”展开“本人变更历史”查看历次操作及时间变化。
- 管理者只可按负责小组调整关联归属，团队直属分工仅由团队负责人管理，不可代改个人内容、状态或实际时间。非项目成员的组长仍可管理本组成员跨项目关联，但不因此获得整个项目的任务访问权。

## 鱼骨式里程碑

- 时间轴旁统一通过“＋ 新增里程碑”创建独立阶段目标，填写名称、负责人和预计完成日期，不自动创建任务；日期留空进入“未规划日期”。各日期旁的“＋”保留，自动带入该日期。通用入口在空列表中同样显示，长时间轴下固定在可视区右侧，窄屏移到时间轴开头。
- 新建团队任务时可选关联一个同项目里程碑；任务详情“更多 → 修改关联里程碑”可调整或解除。一个目标可关联多个任务。
- 点击目标默认查看状态、负责人、预计完成日期及关联任务。目标负责人从底部“确认完成”进入确认，核对尚未完成任务后提交；关联任务的执行状态保持独立。
- 管理者从标题右侧“编辑”修改名称、更换负责人，底部统一“取消／保存修改”；编辑期间不显示其他操作入口。未保存时取消、关闭或按 Esc 会提示放弃修改或继续编辑；保存失败保留输入。
- 日期旁“调整”或拖动到日期分组进入日期调整，须填写原因。重新打开已完成目标须填写原因。
- “更多 → 移出里程碑”展示影响并要求填写原因，确认后保留任务与执行记录并解除关联。日期为空表示尚未规划，不等于计划外。
- 旧版本节点已迁移为独立目标并关联原任务，原任务、分工及历史没有删除。验证见[里程碑与周安排调整记录](里程碑与周安排调整记录.md)。

## 阻塞、拆分与停止执行

主负责人或当前参与人可维护团队任务阻塞，分工和个人事项阻塞由本人维护。可记录原因、等待对象或同项目其他任务。阻塞不阻止开始、不自动顺延；等待任务完成也不自动解除。已接入站内通知，见[生命周期与协作使用说明](生命周期与协作使用说明.md)。

一层拆分需要为所有有效分工选择去向，并具备原负责小组的安排权限，直属分工须由团队负责人迁移。迁移保留原分工标识、进展、个人关联和时间；父任务此后只汇总，不新增执行安排。子任务全部完成仍由主负责人确认父任务整体结束。

团队任务结束、取消后，成员可整理既有内容和补记，但不能绕过重开继续执行或新增关联工作。重开父任务不会自动重开子任务，也不代替成员本人恢复执行。

## 常见反馈

- “内容已变化／409”：其他操作已改变当前版本或确认范围。刷新、核对差异，重新预览后提交。
- “没有权限／403”：服务端会重新检查当前身份、项目和负责小组。查看权限不等于安排权限。
- “关联工作已停止”：先由有权限的人重开上层任务；不得通过解除关联绕过限制。
- 浅色、深色跟随系统；输入框、按钮、焦点和禁用状态共用样式。窄屏看板在自身区域横向滚动，页面无需横向移动。
