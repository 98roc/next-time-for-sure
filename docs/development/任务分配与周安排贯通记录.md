# 任务分配与周安排贯通记录

日期：2026-10-15。范围：网页任务创建、人员分工、周安排和任务卡片动作层级；没有新增数据库结构。

## 实现

- 创建命令返回任务标识，“创建并分配人员”直接进入详情；保留“仅创建”。任务内容编辑移到顶部，人员、周安排、进度与低频管理分区展示。
- `assignment-picker.tsx` 按成员行多选和填写分工，`assign_many` 在同一事务内重验小组权限、成员资格及重复分工，幂等重试不重复创建。沿用单人分配事件和通知规则。
- `task-week-plan.tsx` 与周计划页共享查询、字段解析及移周请求；批量 `save_arrangements` 使用每条任务、分工与安排版本，任何冲突整体回滚。`move_arrangement` 同事务更新来源与目标周，保留人工内容并处理自动延续空记录。
- 草稿对照最新发布副本显示未发布调整，发布副本仍不可变；详情与周计划操作后共同失效周计划、周报和总览缓存。
- 待分配卡片将“分配人员”作为主按钮，“开始”降为次要操作，统一右侧聚合；已有分工时突出开始。成员列表无新增候选时隐藏空表单。

业务边界维护在[研发需求4.3、4.4](../product/研发需求说明书.md)，操作说明见[任务与个人执行](任务与个人执行使用说明.md)和[周计划与周报](周计划与周报使用说明.md)。

## 验证

- Contracts、API、Web、MCP 类型检查及本次代码 ESLint 通过，Vite 生产构建通过。构建仍提示既有大包及第三方 Zod 注释警告。
- 真实 HTTP + MySQL：完整周计划回归通过；新增 `task-workflow.integration.ts` 覆盖首次无上周计划、批量原子性与幂等、越权拒绝、旧版本及并发冲突、双周移动、目标周人工内容保留、自动延续空安排接收来源内容、转交后新旧分工独立和发布快照冻结。
- 隔离临时团队浏览器实测：创建任务后自动进入分工，选择两人并逐行设置小组和内容，保存后自动进入周安排，一键安排本周，编辑目标和投入，打开周计划验证相同回显并移周。390px 窄屏实测无页面横向溢出。
- 实际用户看板只验证按钮层级和未提交的人员选择，没有为用户任务分配人员或修改其周安排。
- 临时测试账号、业务数据、调试服务、浏览器页签和尺寸覆盖已清理。未进行 Electron 运行和外部 Agent 联调，未提交或部署。
