# 周计划与周报使用说明

适用范围：第4阶段网页及登录会话API。业务规则以[研发需求](../product/研发需求说明书.md)4.4、4.7、4.8为准，证据见[第4阶段实施记录](第4阶段实施记录.md)。

## 周计划

从团队工作页进入“团队周计划”，选择周一日期。组长看到当前有权安排的小组分工，团队负责人看到全团队；可按项目、小组和人员筛选。

填写本周目标、预计新增进度和天数后加入共享草稿，三个字段均可空。人员汇总跨项目累计当前可见安排，单列未估算数量，不以超量阻止发布。“从前一周补入未完成分工”只补当前有效的前周分工，保留已有人工安排，目标和估算重新填写。

团队负责人可选任务作为待分配事项加入，预览完整范围、填写说明后确认发布。草稿保存不是发布；后续修改保留原基线，重新发布另存版本。同一确认重复提交不增加版本。已停止安排保留，可明确移出本周草稿，不删除任务。

## 人工标签

团队任务、里程碑节点详情、个人工作卡片均有“人工计划标签”。里程碑外和指定周的周计划外相互独立，修改权限以服务端返回为准。未标记不代表计划内，日期变化不自动设置标签。关联个人工作沿用团队任务标签，需到团队任务修改；原独立标签仍保留。

## 周报整理与发布

进入“团队周报”，选择归属周或直接使用 `/reports?week=2026-11-02` 这样的链接。生成草稿后按项目、小组筛选。每条保留来源、人物和实际发生日期，可改写措辞、合并同任务条目，或勾选排除。原始进展不会随汇报文字变化。

再次生成只补入新来源。已有来源变化时，展开来源对照当前内容；核对后勾选“已核对变化，保留当前措辞”并保存，或排除。排除记录不会因重新生成恢复。调整来源归属周不会修改真实发生日期。

团队负责人预览本周内容与下周计划，填写发布／修订说明后确认。新增来源及未处理变化会阻止发布，需要先整理；已发布内容不自动改变。正式周报按项目展示本周工作＋下周安排，可切换历史版本和复制文字。当前团队全体成员可看正式周报；这不授予草稿或原进展权限。

## 会话接口

所有路径前缀 `/api/v1`。读取带当前登录Cookie；写入同时带同源Origin、`Content-Type: application/json`和会话返回的`X-CSRF-Token`，勿把凭据放入URL。请求结构以共享Zod契约为准。

| 方法与路径 | 用途 |
| --- | --- |
| GET weekly-plans/candidates?teamId=…&week=… | 当前可安排分工 |
| GET weekly-plans?teamId=…&week=… | 有权范围的共享草稿 |
| GET weekly-plans/publications?teamId=…&week=… | 已发布计划及当前操作能力 |
| GET weekly-plans/preview?teamId=…&week=… | 完整发布预览与确认摘要 |
| POST weekly-plans/commands | 建草稿、保存／移除安排、结转、待分配和发布 |
| GET reports?teamId=…&week=… | 受权限保护的草稿、来源、变化提示及公开发布版本 |
| GET reports/preview?teamId=…&week=… | 本周汇报＋下周安排及确认摘要 |
| POST reports/commands | generate、edit、merge、publish、reassign_week |
| GET work-tags?objectId=…&objectKind=task或personal | 有效标签及各维度修改能力 |
| POST work-tags/commands | 按版本人工设置／清除标签 |

保存后重新读取版本；409表示数据或确认范围变化，应刷新核对再提交，不能无条件重试覆盖。403表示当前身份无该范围权限。数据库结构、事务及快照说明集中维护在实施记录，不在本说明复制规则。
