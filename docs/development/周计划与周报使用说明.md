## 周计划

从侧栏进入“周计划”，默认本周，使用上一周／下一周／本周／下周，或选择这一周任意日期。组长看到当前有权安排的小组分工，团队负责人看到全团队；可按项目、小组和人员筛选；团队直属分工无需入组，按“团队直属”筛选，由团队负责人安排与调整，投入按执行人正常累计。

直接点击“新建任务”或“选择已有任务”，在周计划原页内打开任务详情，完成分配人员和安排周次。任务详情默认沿用当前查看周；也可以从项目任务详情操作同一份草稿。首次使用无需上周记录：点击“添加人员”后搜索、多选，选中后才展示分工字段，不默认选中主负责人。保存后留在人员页。任务详情周安排以人员为行、所选周与后一周为列，点击“＋安排”加入该周；列头可整批加入未排人员，已排内容不覆盖。目标、进度与投入通过“已安排·编辑”按人按周补充；移周、移出位于对应格的“更多”。两周分别保存。创建任务、保存分工与保存安排各步骤独立反馈，关闭后保留已保存结果；两周保存部分失败会明确提示已经保存的周。

周中点击任务标题在原页打开详情，按权限变更任务内容、里程碑、人员和工作内容；各入口同步同一任务。人员行直接点击“编辑”。“更多”中的“下周继续做”保留本周并打开下周安排编辑，先回读目标周已有内容；“移至下周”则移出本周。移周规则以[研发需求4.4](../product/研发需求说明书.md#44-周计划预计投入与调整)为准；转交后原分工保留为停止记录，接手人的新分工需明确加入周安排。已发布后修改草稿显示“有未发布调整”，由团队负责人重新发布，原发布副本保持不变。

页面单周展示，顶部切换本周／下周；内容区提供“本周安排／待安排分工／汇总与历史”。默认按项目分组：同一任务只展示一次标题，下方是紧凑人员行；可切换按小组、按个人，筛选独立保留。数量区分别显示去重任务数、人员安排数和待分配数。已完成和停止记录在任务下折叠保留。目标、预计新增进度和天数均选填，不显示空值占位。首次保存自动建立草稿，无需初始化。投入汇总在“汇总与历史”查看，全部未填时隐藏；有已填投入时跨项目累计当前可见安排，单列未估算数量，不以超量阻止发布。自动延续、移出后防止刷新重入及已发布保护仍遵循研发需求4.4。

无项目时按角色引导创建或加入项目；无可安排分工时可直接选择已有任务或新建任务，筛选无结果时提供清除筛选。组长通过“汇总与历史”查看安排，团队负责人通过右上角“预览与发布”进入同一汇总视图。只读角色可将最新发布内容按三个维度查看，历史版本仍在“汇总与历史”，不读取未发布草稿。

在“预览与发布”中，团队负责人可选任务作为待分配事项加入，预览完整范围后直接确认发布，无需填写发布说明。草稿保存不是发布；后续修改保留原基线，重新发布另存版本。同一确认重复提交不增加版本。已停止安排保留，可明确移出本周草稿，不删除任务。

## 人工标签

团队任务详情侧栏和个人工作详情中均有“人工计划标签”。里程碑外和指定周的周计划外相互独立，修改权限以服务端返回为准。未标记不代表计划内，日期变化不自动设置标签。关联个人工作沿用团队任务标签，需到团队任务修改；原独立标签仍保留。

## 周报整理与发布

进入“团队周报”，选择归属周或直接使用 `/reports?week=2026-11-02` 这样的链接。生成草稿后按项目、小组筛选，包括“团队直属”。直属分工及关联个人工作的进展只由团队负责人整理，执行人仍可补记本人进展；其所属组长不会因此获得整理权限。每条保留来源、人物和实际发生日期，可改写措辞、合并同任务条目，或勾选排除。原始进展不会随汇报文字变化。

首次从空状态“生成周报草稿”，已有草稿通过右上角“同步新增工作”补入新来源。已有来源变化时，展开来源对照当前内容；核对后勾选“已核对变化，保留当前措辞”并保存，或排除。排除记录不会因重新生成恢复。调整来源归属周不会修改真实发生日期。

团队负责人通过右上角“预览与发布”打开侧栏，核对本周内容与下周计划，填写发布／修订说明后确认。新增来源及未处理变化会阻止发布，需要先整理；已发布内容不自动改变。正式周报按项目展示本周工作＋下周安排，可切换历史版本和复制文字。当前团队全体成员可看正式周报；这不授予草稿或原进展权限。

## 会话接口

所有路径前缀 `/api/v1`。读取带当前登录Cookie；写入同时带同源Origin、`Content-Type: application/json`和会话返回的`X-CSRF-Token`，勿把凭据放入URL。请求结构以共享Zod契约为准。

| 方法与路径 | 用途 |
| --- | --- |
| GET weekly-plans/candidates?teamId=…&week=… | 当前可安排分工 |
| GET weekly-plans?teamId=…&week=… | 有权范围的共享草稿 |
| GET weekly-plans/publications?teamId=…&week=… | 已发布计划及当前操作能力 |
| GET weekly-plans/preview?teamId=…&week=… | 完整发布预览与确认摘要 |
| POST weekly-plans/commands | 建草稿、单条／批量保存、移除／移周、结转、待分配和发布 |
| GET reports?teamId=…&week=… | 受权限保护的草稿、来源、变化提示及公开发布版本 |
| GET reports/preview?teamId=…&week=… | 本周汇报＋下周安排及确认摘要 |
| POST reports/commands | generate、edit、merge、publish、reassign_week |
| GET work-tags?objectId=…&objectKind=task或personal | 有效标签及各维度修改能力 |
| POST work-tags/commands | 按版本人工设置／清除标签 |

保存后重新读取版本；409表示数据或确认范围变化，应刷新核对再提交，不能无条件重试覆盖。403表示当前身份无该范围权限。数据库结构、事务及快照说明集中维护在实施记录，不在本说明复制规则。

当前周报在“整理周报”和“已发布版本”间切换。整理条目默认显示正文，展开“编辑这一条”才填写措辞；来源追溯按需展开，不展示内部来源标识。
