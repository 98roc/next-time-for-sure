后续统一调整见[工作区布局与交互统一记录（2026-10-15）](工作区布局与交互统一记录.md)，包括紧凑筛选、减少重复外框、周计划卡片及个人事项详情。本页保留各次改造的历史证据。

## 已落地

| 范围 | 当前行为 |
| --- | --- |
| 工作区 | 共享窄侧栏、错位方块标志、雾蓝控件与清晰的当前导航；普通成员登录后进入我的工作，超管进入账号管理；受保护链接登录后返回原目标。移除早期工程状态首页与失去调用的健康检查前端封装，后端健康接口继续保留。 |
| 项目 | 看板、里程碑、需求分别切换；项目与视图进入URL，任务深链接打开统一详情侧栏；搜索只过滤展示，不截断排序命令所需的完整任务版本集合。 |
| 里程碑 | 新增内容只填名称，已有日期组自动带入日期，留空进入未规划；可加入已有任务。节点上按既有权限改名、保存累计进度、开始与确认完成；改期及移出保留原因，不删除原任务。默认负责人见产品需求4.2。 |
| 鱼骨布局 | 上下分支共享日期主轴，同日显示多个事项及数量；窄屏转换为纵向。落点提示使用绝对定位，不再撑高分支使落点移动；进入、经过落点都明确接受移动操作。 |
| 个人工作 | 日常卡片仅显示标题、状态、计划日期、阻塞、检查项摘要与快捷操作；详情、进展、历史及低频管理进入侧栏。新建事项和分类管理分别打开；不再让用户输入内部排序位置。 |
| 周计划与周报 | 周次支持前后切换及任意日期归一化；周计划用紧凑卡片和按需编辑窗口，编排与预览发布分开。周报默认阅读条目，按需编辑，来源追溯不暴露内部标识；已发布版本独立切换。 |
| 团队与通知 | 超管仅有账号、团队两个入口；团队内按成员、小组、项目与总览分区，采用明确按钮与弹窗，无权管理时隐藏操作；归档交接与通知分离。编辑项目成员时回填现有角色；分配执行人时按所选小组筛选。 |
| 账号与品牌 | 登录后返回工作区；账号密码和Agent访问令牌分区。网页favicon与Electron运行时窗口／托盘图标采用错位方块。 |

## 验证证据

- `scripts/pnpm.ps1 check`：类型检查、Lint、8项现有单元测试和全部工程构建通过；最终导航调整后另行通过前端构建与Lint。Vite仍提示主包超过500kB，尚未进行路由分包优化。
- `scripts/pnpm.ps1 work:smoke`：真实HTTP＋MySQL验证权限、版本竞争、同日节点、未规划、移出再加入、共享任务、人员分工、个人事项、父子拆分、排序及阻塞；随机夹具由脚本清理。
- `scripts/pnpm.ps1 weekly:smoke`：真实HTTP＋MySQL验证周计划候选范围、跨项目小组权限、发布版本、再生成及隐私边界；随机夹具由脚本清理。
- 浏览器实际登录示例成员后进入我的工作；验证项目视图切换、名称新增、改名、保存45%累计进度、改期创建新日期组、移出保留任务及打开同一任务侧栏。
- 实际拖动“确认首期交付范围”至另一日期组，显示确认并保存；API回读日期一致，随后用API恢复示例原日期。
- 新增／改名／进度／移出结果经过API与MySQL回读：测试节点名称正确、进度45%、已移出里程碑、日期为空。随后仅清理该测试节点及其关联通知、幂等和历史记录，未清理其他工作。
- 周次输入任意工作日可归入 `2026-11-02～2026-11-08`；采用input事件避免某些浏览器填日期后界面范围不更新。
- 390×844窄屏检查纵向鱼骨、导航可访问、新增窗口及Esc关闭；文档宽度未超出视口。深色、浅色页面已目视检查，浏览器控制台无错误。

## 保留与边界

- 示例项目保留5条有业务名称的未开始事项，覆盖多个日期、同日多事项及未规划，供后续试用；不表示真实研发进展。临时“交互验收节点”已清理。
- 本轮没有数据库结构变更，没有修改后端权限或状态规则。管理者不会因为能维护规划而获得代改他人任务内容或进度的权限。
- 原型源码与导出保留为设计基准，不作为正式应用运行证据；正式页面行为以代码、产品规则及本记录为准。
- Electron图标源码已构建及通过现有测试；本轮没有重新打包、安装客户端，也没有重新进行完整Windows系统通知验收。
- 未对每个角色的全部页面路径逐一进行人工操作，权限依赖真实API回归；尚未验证大规模节点性能及真实手机浏览器，390像素验证是桌面浏览器视口模拟。

## 角色引导与操作层级调整（2026-10-14）

- 通知收至右上角铃铛与未读数量，移除侧栏重复入口。团队负责人看到“团队管理”，普通成员看到“团队成员”；超管仍仅有账号与团队管理。
- 主内容靠近侧栏起始位置，去掉大屏左侧多余留白。统一空状态、筛选栏、主要按钮、次要链接与弹窗按钮宽度。
- 项目页直接创建项目，并在回读唯一匹配新项目后进入该项目；无项目按角色引导创建或加入。团队管理提供成员、小组、项目的协作顺序和项目工作区入口。
- 个人页范围改为紧凑页签，刷新降为次要操作；没有项目和事项时隐藏筛选栏，没有本人事项时不展示空分类看板（分类仍可管理）。分类改为行内名称、保存和移除确认；“记录进展”直接展开对应表单。任务详情直接展示分工，无分工或无小组时说明下一步。
- 周计划的周次、筛选与内容分区，首次安排自动建草稿；无项目、无分工和筛选无结果分别引导。周报生成、同步与预览分阶段显示，发布确认集中到侧栏；只读身份文案不引导编辑。

本轮验证：

- 前端严格类型检查、构建及ESLint通过；已有大包和第三方注释构建提示仍保留。
- 浏览器分别检查团队负责人、兼任组长的研发成员、仅项目经理、普通研发成员及超管的入口与可见操作。实际使用隔离测试团队创建两个项目、分类改名、首次周安排、成员进展记录、周报生成和发布预览；没有确认发布周报。
- MySQL回读确认两个项目、分类名称及周安排目标已保存。筛选空结果可清除并恢复条目；新建项目后自动进入新项目。

### 项目成员、紧凑卡片与误开始撤销

- 项目“管理成员”在一张列表中多选新增成员、同行勾选每人的角色；已有成员角色直接回显和编辑，不再单独展开表单。搜索保留隐藏行的选择，新选择成员默认研发角色，一次保存全部增量。保存成功后刷新相关列表并自动关闭弹窗；编辑使用起始版本，失败保留选择并提供放弃修改、重新加载入口。
- 任务卡片负责人和日期并排，正文移除展开式排序操作，右上角“⋯”保留键盘/触屏备用操作；常用开始、结束入口保持可见。普通单行标题卡片在当前浏览器实测约111像素高。390像素视口看板内部横向滚动，页面无横向溢出。
- 进行中任务新增“撤销开始”，拖回待开始也调用同一命令。后端校验及业务边界见研发需求4.6；不删除历史、不改关联执行记录。
- 类型检查、前后端构建、修改文件ESLint通过；真实HTTP/MySQL工作回归通过，包含撤销开始的权限、并发冲突、时间恢复及已有累计进展/时间修正/分工/个人进展拒绝。隔离测试账号、团队和业务记录由夹具清理。
- 浏览器验证成员搜索、研发默认角色、已有角色回显、无角色禁止保存、取消操作，以及卡片菜单和Esc关闭。未替真实团队添加人员，成员新界面的写入未在浏览器提交；后端成员命令沿用既有组织回归。原生拖拽本轮仅核对保留的处理器与可拖动属性，未重新完成实际鼠标拖放；Electron与外部Agent未重新验收。
