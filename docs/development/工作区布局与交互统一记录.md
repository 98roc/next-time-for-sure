# 工作区布局与交互统一记录

日期：2026-10-15。范围：当前 Web 工作区的布局、筛选、卡片与个人事项详情。本记录接续[工作区体验改造记录](工作区体验改造记录.md)，说明本轮实际修改及验证边界。

## 问题与修改

| 页面 | 发现的问题 | 本轮处理 |
| --- | --- | --- |
| 周计划 | 周次、两层页签、筛选连续占据多行；卡片按钮随正文长短上下错位 | 合并为“本周安排／待安排／汇总与历史”；筛选与页签同行，周次旁显示草稿状态；卡片底部固定操作区，常用编辑突出，移周与移出收进“更多” |
| 项目 | 单独一整行项目切换与搜索；看板外框内再套列框，重复标题 | 多项目切换放在标题旁，只有一个项目时省略；搜索和刷新并入视图栏；移除看板外层卡片和重复标题，只保留状态列及任务卡片 |
| 项目筛选 | 筛选后的总数、列数与实际卡片不一致 | 三者共用展示范围；排序仍使用完整任务集合，避免搜索截断排序版本集合 |
| 我的工作 | 卡片外单独拖拽按钮，标题落在状态后；开始、完成、记录进展并列；详情堆叠多个表单 | 标题前置、整卡拖动、底部状态和下一步动作；待开始突出“开始”，进行中突出“记录进展”、完成为次要动作；标题打开内容，“···”打开更多设置 |
| 个人事项详情 | 内容编辑隐藏，进展表单埋在低频设置后，日期竖排且空时间反复显示 | 分为“事项内容／进展记录／更多设置”；明确“编辑内容”入口；进展先填内容，日期桌面并排；分类、关联、时间修正、标签与历史集中到更多设置；没有实际时间时不显示“未记录”占位 |
| 周报 | 筛选另占一行，重复内容标题 | 有草稿内容时将筛选并入视图栏；保留整理与已发布版本区分，发布仍从顶部入口进入 |
| 团队管理 | 搜索框横向撑满，标签和操作占据过多空间；列表外框重复 | 紧凑搜索和状态筛选，操作集中右侧；小组、项目列表取消无意义外框，保留行分隔 |
| 团队总览 | 大外框套项目卡片，标题和间距重复 | 去掉外框与重复标题，周次与查看维度同行；压缩项目卡片小标题间距；缺省投入不显示为零或“未估算”占位 |
| 通知与归档交接 | 列表外框套条目，通知按钮逐行堆叠 | 移除集合外框；通知标题、时间与操作分左右布局，窄屏换行；刷新降为次要动作 |

## 统一规则

1. **标题说明当前对象，工具栏服务当前列表。** 页面视图尽量只保留一层切换，筛选与该视图同行；空间不足时换行，不把输入框强行拉满。
2. **边框用来区分对象。** 看板保留状态列与任务卡片，去掉覆盖整个看板的装饰性外框。里程碑时间轴的画布边界、成员表格边界和确认弹窗仍有明确用途，保留。
3. **一个操作区突出一个主要动作。** 卡片优先显示当前下一步；低频操作放入“更多”。编辑表单的取消与保存同排右对齐，进展分区以“记录进展”为主要动作。
4. **卡片内容变化不挤乱操作位置。** 周计划卡片等高排列，操作区靠底；任务标题采用统一颜色及悬停效果，不因是否访问过而出现不同强调。
5. **没有填写的可选信息不占位。** 目标、投入、预计新增进度、实际时间等只在存在时展示；数字 `0` 是有效值，不能被空值判断隐藏。没有目标和投入时也不留空行、孤立分隔符。
6. **保留有业务意义的状态。** 加载失败、无筛选结果、无进展记录、未发布状态仍须可见。有部分投入已填写时，人员汇总保留未估算数量，避免把缺失误认为零；全部未填则隐藏投入汇总。
7. **高频操作直接可见，低频设置集中。** 个人内容默认阅读并提供编辑入口；进展独立分区；切换分区保留未保存内容。内容保存成功退出编辑，失败保留输入；进展保存成功清空已提交表单，失败保留。
8. **桌面与窄屏共用语义。** 窄屏筛选自动换行，日期转为单列，看板只在自身区域横向滚动。表单保留可访问标签，菜单支持键盘关闭，分类移动仍有表单备用入口。

## 保留与实现边界

- 项目任务的分工、周安排、执行及更多分区继续使用现有业务命令；没有增加管理者代改他人执行事实的权限。
- 个人事项的分类、开始、完成、内容、检查项、进展、关联、时间修正与历史能力保留。卡片、详情、表单拆为独立组件，避免再次把所有交互塞进同一个卡片函数。
- 分类管理与项目成员弹窗已有按行编辑结构，本轮没有再次重做。里程碑保留时间轴画布及原有详情操作。
- 任务内周安排、周计划预览、复制文字和团队总览同步隐藏空值提示。新生成的计划行不再写入“目标未填写”；历史已发布快照不追溯改写。
- 本轮没有数据库结构迁移，没有提交、推送或部署；不清理已有的其他开发改动。

## 验证记录

- 前端严格类型检查、相关 TypeScript 文件 ESLint、Vite 生产构建通过。构建仍有第三方 Zod 注释与主包超过 500 kB 的既有提示。
- API 编译及真实 HTTP＋MySQL 周计划回归通过，覆盖候选权限、发布、结转、任务与周安排贯通及团队直属；随机回归夹具由脚本清理。这不等于全部页面和角色均经过人工验收。
- 浏览器使用当前团队负责人身份检查周计划三张内容长短不同的卡片，操作区对齐；筛选、清除、更多菜单、Esc 关闭、编辑取消和汇总切换正常。未填写目标／投入不出现占位，任务内周安排同样处理。
- 项目搜索“档案”时，总数、待开始列数与可见卡片均为 1。团队成员页、团队总览、周报空草稿及通知页做了页面检查。周报有正文时的筛选布局经过代码与构建检查，本轮未为此写入真实周报内容。
- 个人事项验证：标题进入内容、明确编辑入口、检查项未保存输入跨分区保留、取消后丢弃、更多设置入口完整。390×844 模拟视口下，详情与看板页面宽度未溢出；日期自动转单列。未在用户的真实事项上提交开始、完成、内容或进展变更，保存回调及错误保留经过代码检查，不将其表述为已完成真实写入验收。
- 本轮主要目视检查深色桌面页面及 390px 模拟视口；没有重新进行所有角色、浅色主题、真实手机、Electron 或外部 Agent 全流程验收。
- 本次浏览器测试页、尺寸覆盖和未保存的试验输入在检查后清理，原有开发服务与用户业务数据保留。
