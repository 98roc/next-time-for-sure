# 工程基线与验收对照

基线：产品v0.23、研发v1.7、实施计划v1.2。本文区分目标设计与当前代码，不替代产品业务规则。工程底座、账号会话及组织权限已实现；第3阶段已完成需求、分工、个人执行及看板里程碑验收，完整组织生命周期及周报仍待实施。

## 工程职责

| 目录 | 职责 | 当前范围 |
| --- | --- | --- |
| apps/api | NestJS模块化单体，统一权限、业务事务、数据访问 | 探针、迁移、身份会话、组织、需求、分工与个人事项 |
| apps/web | React页面，服务端状态使用TanStack Query | 工程状态、账号安全、团队与项目、团队工作和个人空间 |
| apps/desktop | Electron系统能力入口，复用网页 | 隔离且禁用Node集成的窗口骨架；托盘和安装包待第6阶段 |
| apps/mcp | 本地stdio协议适配，不复制业务逻辑 | system_health只读公开探针；认证与业务工具未实现 |
| packages/contracts | 各入口共用类型和运行时校验 | 探针、身份、组织、需求、分工和个人事项契约 |
| packages/ui | 共用视觉变量与基础组件 | 已确认配色、字号基础与状态标记 |
| scripts | Windows兼容启动、检查与进程回收 | 项目nvm版本、固定pnpm、开发启动、冒烟测试 |

组织接口已执行输入、当前身份、范围、业务条件和版本检查，并在事务内写入及审计；后续业务沿用相同原则，按需要增加确认及幂等。Controller及MCP层不得自行实现另一套规则。当前只开放工程公开探针与登录，其余已有接口均要求会话。

## 对象关系设计（当前及后续阶段边界见验收映射）

| 对象 | 关系与独立记录边界 |
| --- | --- |
| 账号、团队成员 | 一个账号最多属于一个当前团队；移出不删除旧团队记录；私人事项仅绑定本人 |
| 小组成员 | 账号与小组多对多；查看范围可合并，不能因此调整其他小组负责的分工 |
| 项目成员、角色授权 | 项目归属单一团队；团队与项目角色分别记录作用范围；预设角色权限不覆盖固定业务禁令 |
| 需求 | 保留每次提交、修改和处理历史；一次接收只生成一条来源团队任务 |
| 团队任务 | 可包含一层子任务；父任务拆分后只汇总和整体结束，不再承载新执行安排 |
| 人员分工 | 关联可执行团队任务、执行人、负责小组及分配来源；转交创建接手人的分工并保留原记录 |
| 周安排 | 关联人员分工及归属周，承载周目标和预计投入；不在个人任务或父任务重复估算 |
| 个人任务、分类、检查清单 | 分类与执行状态分离；个人任务至多关联一条可执行团队任务，清单不独立排期、计时或汇报 |
| 进展记录 | 关联分工或个人工作，分别保存内容、实际发生日期、归属周和作者；来源关联用于去重，不按任务时间跨度推算每周工作 |
| 周计划、周报 | 草稿与发布版本分离；快照保留文本及来源信息，不能依赖源记录仍存在；周报合并和排除保留来源映射 |
| 通知与审计 | 业务事件、每用户通知、已读状态及每桌面展示去重分别表达；与业务写入保持可追踪一致性 |
| 会话、个人Token | 会话与Token分离；Token只存摘要，权限每次读取当前状态；Token管理仅允许登录会话 |

实现时数据库唯一约束至少覆盖需求接收结果、同一业务操作的幂等键和每用户事件通知；乐观版本用于检测冲突，事务覆盖关联对象的同步变化。MySQL 5.7的DDL不能依赖事务回滚，迁移失败需核对已执行结构后以显式修复处理。

## 状态及操作设计（任务执行已实现，周报与项目生命周期待后续阶段）

| 对象 | 操作路径 | 不允许的隐式变化 |
| --- | --- | --- |
| 需求 | 待处理→要求补充／暂缓／拒绝／撤回／接收；拒绝和撤回后显式重提，暂缓显式恢复 | 修改内容不自动重提；并发接收不能使用旧版本或重复生成任务 |
| 团队任务 | 待开始→进行中→已完成；取消独立，重开保留历史 | 阻塞不是状态列；成员完成和子任务完成不自动结束整体 |
| 人员分工 | 本人开始、确认完成；转交、退出、取消、整体结束分别保留原因和来源 | 整体结束不伪造本人完成与时间；分工结束不自动改个人状态 |
| 个人任务 | 本人开始、完成和重新开始；分类移动只改变组织方式 | 新增或重启关联工作仅按需求恢复本人分工；团队结束后不能绕过重开继续执行 |
| 周计划／周报 | 按需生成草稿→人工整理→发布→修订发布 | 源数据变化、重生成、删除和归属变更不覆盖已发布快照 |
| 项目 | 活跃→归档→恢复 | 归档前检查未结束执行事项；管理者不能代改个人事实以满足归档 |

重开、取消、结束和其他需要确认的操作绑定具体内容与版本；Agent在对话中确认，相关内容发生变化后必须重新确认。

## 权限实施矩阵（以研发第3节为规则源）

| 操作 | 允许身份及范围 | 服务端固定限制 |
| --- | --- | --- |
| 预设角色权限配置 | 超管 | 不能开放私人事项或代改他人执行事实 |
| 团队角色与小组管理 | 团队负责人；团队负责人交接由超管 | 不能扩大自身授权，不跨团队 |
| 需求接收、任务主负责人指定 | 项目研发负责人、团队负责人 | 指定主负责人不自动分配执行人员或入周计划 |
| 人员安排 | 负责小组组长；团队负责人可跨组 | 其他组长不能因成员多组身份覆盖安排 |
| 本人执行与补记 | 本人（网页、桌面、Agent相同） | 先检查团队及分工的执行限制，不代改他人事实 |
| 整体结束 | 任务主负责人 | 提示未完成范围并确认；不伪造个人完成 |
| 草稿整理及发布 | 组长按范围整理；团队负责人发布 | 草稿访问及源记录访问保持原权限 |
| 已发布周报查看 | 当前团队全部成员 | 不授予源记录访问权；私人事项排除；移出后失去访问 |
| Token生成及撤销 | 本人登录会话 | 个人Token或Agent不能调用Token管理接口 |
