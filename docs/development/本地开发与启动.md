# 本地开发与启动

> 适用当前 V2.0 开发分支；生产尚未迁移。实现与分层验收见[V2.0 实施记录](V2.0实施记录.md)，完整迁移和多端验收完成前不可作为生产发布版本。

本文说明 Windows 本地开发环境。当前入口与版本边界见[项目说明](../../README.md)，服务器发布使用[Docker部署流程](Docker部署.md)。

## 运行环境

- Windows PowerShell 5.1，nvm-windows。
- 项目Node版本以根目录`.node-version`为准，pnpm版本固定于`package.json`；不使用系统默认Node执行本项目。
- MySQL 5.7；当前迁移工具仅接受`next_time_for_sure`独立库和5.7服务端。
- `scripts/pnpm.ps1`通过`NVM_HOME`定位项目Node，不执行全局`nvm use`；首次运行在忽略目录`.cache/toolchain`安装固定pnpm，不更改全局包管理器或npm配置。

本机已将校验过SHA256的Node发行包安装到nvm版本目录，`nvm list`可识别。默认Node选择保持不变。新机器可执行`nvm install`安装`.node-version`指定版本；镜像不可用时须使用可信发行源并核对校验值。

## 初始化与检查

在仓库根目录执行：

```powershell
# 首次配置；已有 .env.local 时不要覆盖。
Copy-Item .env.example .env.local
# 编辑 .env.local，填写数据库账号、密码。

.\scripts\pnpm.ps1 install --frozen-lockfile
.\scripts\pnpm.ps1 build
.\scripts\pnpm.ps1 db:migrate
.\scripts\pnpm.ps1 db:status
.\scripts\pnpm.ps1 check
.\scripts\pnpm.ps1 smoke
```

`.env.local`已被Git忽略。数据库凭据仅由后端加载；前端不使用`VITE_`变量存放凭据。环境变量优先于本地文件。示例配置不含真实密码；不要把Token、密码或完整连接串复制进日志或文档。

依赖下载使用项目`.npmrc`指定的npm registry；未修改用户全局registry。Electron下载遇到网络问题时可仅在当前PowerShell设置`$env:ELECTRON_MIRROR`后重试安装，不需要更改全局配置。

`db:migrate`先显示不含密码的目标及MySQL版本，再创建独立库（如不存在），持有命名锁执行版本化迁移。关闭TypeORM自动结构同步和API启动自动迁移。重复执行不会重复应用已记录迁移。MySQL DDL不能作为可回滚事务处理；失败时先核对迁移记录与实际表结构。一般迁移不得盲目删库重试；本轮已允许为 V2.0 重建本地开发库，但必须确认目标且按[迁移准备](V2.0迁移与研发准备.md)执行，绝不用于生产。

## 启动

```powershell
.\scripts\pnpm.ps1 dev
```

默认访问：

- 网页：`http://127.0.0.1:5174`
- 登录改密：`http://127.0.0.1:5174/account`
- 账号管理（超管）：`http://127.0.0.1:5174/accounts`
- 团队管理：`http://127.0.0.1:5174/organization`
- 后端存活：`http://127.0.0.1:3100/api/v1/health/live`
- 数据库就绪：`http://127.0.0.1:3100/api/v1/health/ready`
- OpenAPI页面：`http://127.0.0.1:3100/api/docs`

终端按Ctrl+C停止本次启动的进程组。`dev`自动编译基础包和API，API源码由TypeScript监听编译，前端由Vite热更新；修改共用包后需重新构建该包。端口被占用时失败退出，不自动切换端口。本地开发默认仅监听本机回环地址；局域网访问与服务器发布使用[Docker部署流程](Docker部署.md)，不要把开发配置覆盖为生产配置。

可选桌面窗口底座（先启动前后端）：

```powershell
.\scripts\pnpm.ps1 --filter @ntfs/desktop dev
```

V2 已删除桌面业务通知。配置与安全隔离的单元测试不能替代 Electron 实机验收；当前证据见[V2.0 实施记录](V2.0实施记录.md)。

## MCP与Codex

`scripts/mcp.ps1`使用nvm项目版本启动stdio适配器，不输出协议外文本。不配置Token时仅提供`system_health`；配置个人Token后开放业务工具，见[桌面与Agent使用说明](桌面与Agent使用说明.md)。

按[Codex MCP官方说明](https://developers.openai.com/codex/mcp/)配置本地stdio服务。示例中的项目路径按实际目录替换，Windows路径使用TOML字面量字符串：

```toml
[mcp_servers.next_time_for_sure]
command = 'powershell.exe'
args = ['-NoProfile', '-File', 'G:\work\project\next-time-for-sure\scripts\mcp.ps1']

[mcp_servers.next_time_for_sure.env]
MCP_API_URL = 'http://127.0.0.1:3100'
```

构建并启动API后，在Codex要求调用`system_health`。本次自动验证使用单次配置，不修改全局Codex设置。Token、认证拒绝及 V2 业务确认使用 agent:smoke 验证；外部模型客户端是否通过以实施记录为准。

## 检查与恢复边界

- `check`包含严格类型检查、ESLint、配置和错误路径测试、全工作区构建。
- `db:migrate`和`db:status`均检查当前库所有表及字段的中文注释；漏写中文COMMENT时返回失败。历史迁移及中文注释核验结果见[V1 摘要](../archive/v1/README.md)，当前状态须运行命令重新检查。
- `smoke`使用空闲端口启动API和前端预览，验证真实MySQL就绪、OpenAPI、代理及MCP协议，然后关闭自己创建的进程。不会新建或删除业务数据，也不会终止已有服务。
- 浏览器布局及真实Codex调用须单独记录，不能由HTTP测试替代。
- `identity:smoke`验证真实登录会话、改密、禁用和退出；`organization:smoke`验证基础组织权限、版本冲突、历史删除保护及旧入口撤除。随机回归数据默认清理。
- 现有部署脚本已提供迁移前备份；恢复演练仍缺证据，V2.0 迁移前须完成，不把备份文件存在等同于恢复可用。

## 业务与页面验收

- `v2:smoke`：真实 HTTP/MySQL 验证跨入口任务、权限、事务、并发、历史、成员移出和共享稿保护。
- `token:smoke`：Token 摘要、管理隔离、到期、禁用、撤销及即时项目权限。
- `agent:smoke`：在 Token 回归中连接真实 stdio MCP 服务，执行查询、创建、幂等重试、越权拒绝、预览与确认删除。

以上脚本仅连接本机开发库，清理自建随机夹具与监听器，不提供旧版示例保留参数。浏览器交互、布局、Electron 和外部 Agent 客户端独立验收，证据与未完成项见[V2.0 实施记录](V2.0实施记录.md)。Vite 代理显式保留 Host，确保写入满足后端同源校验。
