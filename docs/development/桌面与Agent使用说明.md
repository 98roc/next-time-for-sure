# 桌面与Agent使用说明

> 适用 V2.0；服务端已上线，2026-10-20 桌面 [2.0.1](https://github.com/98roc/next-time-for-sure/releases/tag/v2.0.1) 已发布至默认 GitHub 自动更新源，可从客户端“检查更新”获取。真实 Electron 运行及 MCP 协议验证通过，外部 Agent 客户端按用户决定跳过；分层证据见[V2.0 实施记录](V2.0实施记录.md)。

本文说明客户端连接、更新与 V2 MCP 工具用法。真实 stdio 协议验证与外部模型客户端验收分别记录，不互相替代。

## 个人Token

登录`/account`，填写用途名称，选择到期时间或确认永久有效风险。生成后立即保存完整Token至不入库的本地文件，例如`.agent-token.local`，文件只含Token。离开页面后不再提供明文。疑似泄露或停用时在同一页面撤销。

Token代表当前用户，不额外配置读写或项目范围。被禁用、到期、撤销时拒绝；成员或角色变化实时生效。Agent不能创建、查询列表或撤销Token，即使同时携带登录Cookie也拒绝管理请求。

## MCP接入

先构建并启动API。按[Codex官方MCP配置](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)配置本地stdio；将示例路径替换为实际路径，不把明文放进配置或对话：

```toml
[mcp_servers.next_time_for_sure]
command = 'powershell.exe'
args = ['-NoProfile', '-File', 'G:\work\project\next-time-for-sure\scripts\mcp.ps1']

[mcp_servers.next_time_for_sure.env]
MCP_API_URL = 'http://127.0.0.1:3100'
NTFS_TOKEN_FILE = 'G:\work\project\next-time-for-sure\.agent-token.local'
```

也可由调用进程提供`NTFS_ACCESS_TOKEN`，不得与文件配置同时使用。地址只接受本机HTTP origin，不接受外部URL、路径、查询或内嵌凭据。不配置Token时仅启用`system_health`。

| 工具 | 范围 |
| --- | --- |
| business_query | 身份、组织、V2 工作区、区间组合、任务历史与总结 |
| business_command | 基础组织管理、V2 任务、待建、里程碑、个人分类、日期安排、共享文字及团队配置；复用网页严格契约 |
| business_preview | 删除、取消安排、解除里程碑、完成里程碑、调整日期和成员配置的当前影响及确认摘要 |
| system_health | 无需认证的工程探针，不表示身份或业务成功 |

先查询最新状态，必要时预览并在对话确认；版本变化返回409后重新查询和确认。创建重试沿用同一`operationId`。超时可能已提交，先回读再判断，不直接重复创建。工具固定白名单不提供任意HTTP代理，权限仍由API负责。

三个Skill随仓库放在`.agents/skills`，可在该仓库的Codex中明确调用`$ntfs-backlog`、`$ntfs-team-tasks`、`$ntfs-weekly-reports`。其他工作目录可按客户端支持的Skill加载方式使用这些目录；不复制凭据。周报Skill对仅有项目角色的用户只做可见内容总结，不写入团队草稿。

## Windows客户端

本机使用时先启动API与网页；也可连接已部署的局域网或公网服务，再运行：

```powershell
.\scripts\pnpm.ps1 --filter @ntfs/desktop dev
# 构建Windows x64安装程序
.\scripts\pnpm.ps1 --filter @ntfs/desktop package
```

客户端加载配置的网页，不将业务前端打包进安装程序。网页发布后，使用“客户端 → 刷新网页”或重新打开页面即可加载新版；托盘和更新功能等桌面代码通过安装包升级。客户端不包含数据库或后台服务，也不支持离线写入。

### 连接配置

客户端跟随 Windows 应用的深浅色主题，网页内容和加载底色同步变化，不固定浅色。浏览器版跟随浏览器提供的系统配色偏好；主题变化不改变侧栏的收起状态。

窗口原生菜单栏默认收起，以规避部分 Windows 多显示器缩放环境下菜单底部亮线的显示异常；按一次 `Alt` 可唤出“客户端”菜单，系统托盘仍提供相同操作，`Ctrl+R` 仍可刷新。该兼容处理需要安装新版客户端；隐藏菜单不等同于已修复系统原生菜单的重绘问题，跨屏显示效果仍需在出现问题的双屏环境验证。

从窗口“客户端”菜单或系统托盘打开“客户端设置”，分别填写网页地址和安装包更新地址，点击“保存并重启”。网页连接失败时仍可打开本地设置窗口。配置损坏时会提示重新填写，不会静默覆盖原文件。

| 配置 | 示例与规则 |
| --- | --- |
| 网页地址 | 本机`http://127.0.0.1:5174`、局域网`http://192.168.1.10:5174`、公网`https://work.example.com`；只填写站点根地址，不包含页面路径 |
| 安装包更新地址 | 默认`https://github.com/98roc/next-time-for-sure/releases/latest/download/`；也支持本机、局域网或公网静态目录，目录提供`latest.yml`和安装文件，留空则不启用更新 |
| 启动时检查 | 默认开启；关闭后仍可从菜单手动检查 |

两个地址独立配置，均不接受内嵌账号密码、查询参数或锚点。公网建议使用HTTPS；HTTP更新目录必须是可信且受控的网络。配置保存在Electron用户数据目录`desktop-settings.json`，通常为`%APPDATA%\@ntfs\desktop\desktop-settings.json`（以实际Electron用户数据目录为准）。升级安装不清除配置。

已保存配置优先于环境变量。首次启动可通过`DESKTOP_WEB_URL`、`DESKTOP_UPDATE_URL`预置地址；均未设置时默认连接`http://127.0.0.1:5174`并从项目公开GitHub Releases检查版本。公开源码及安装包不内置私有服务器地址、配置或凭据，实际服务器仅在使用者电脑上配置。切换站点后按完整origin（协议、主机、端口）隔离Cookie，首次进入新站点须重新登录；默认本机站点沿用旧版数据。

局域网或公网接入还需部署网页及同源`/api/v1/`接口，配置监听地址、反向代理、网络访问和HTTPS。本功能仅配置客户端连接，不会自动部署服务或开放端口。

### 客户端版本更新

启动检查与菜单“检查更新”共用流程：发现新版本后确认下载，菜单及任务栏显示下载进度，下载完成后确认重启安装。“稍后”不会安装，普通退出也不自动安装；可稍后点击菜单中的“重启安装”。更新期间继续使用网页，失败后当前版本继续可用，可重新检查重试。开发模式不下载或安装更新。

首次从不具备更新入口的`0.1.0`升级到`1.0.0`，需要手动运行新版安装包。后续版本使用更新目录分发：

1. 修改`apps/desktop/package.json`的版本号，必须高于已发布版本；执行上述`package`命令。
2. 在项目GitHub仓库创建对应版本的Release，将`apps/desktop/release/`内的`NextTimeForSure-<版本>-Setup.exe`、对应`.blockmap`及`latest.yml`作为附件上传，确认完整后发布为最新稳定版。使用自建更新目录时，先上传安装文件，最后发布`latest.yml`。保持生成文件原名，不手工修改校验值。
3. 更新服务需允许客户端下载这些静态文件，避免缓存旧`latest.yml`；不把网页登录重定向当作更新响应。当前不支持需要额外Token的私有更新源。
4. 在客户端配置更新目录并检查更新。网页服务和更新目录可部署在同一服务器，也可独立部署。

打包命令明确使用`--publish never`，只生成安装包和更新元数据，不会上传文件；发布时只上传上述三个文件，不上传用户配置或本地部署资料。实现采用[electron-updater的NSIS与generic更新目录](https://www.electron.build/v26/docs/features/auto-update/)，下载组件校验安装文件的SHA-512；当前沿用未签名安装包，尚未配置发布者签名证书，不应把校验值视为发布者身份认证。

窗口、托盘、安装程序及快捷方式共用网页`favicon.svg`生成的错位方块图标，系统名称保持“下次一定”。图标生成脚本随`build/dev/package`执行，避免维护两套品牌图形。

关闭窗口隐藏到托盘，托盘提供打开窗口、刷新、设置、检查更新和退出。退出清理托盘并结束进程。V2 已移除旧业务通知与轮询；本次新增通知见下节。旧版去重文件不再读取，不自动删除用户已有文件。

## 七天消息与系统通知（当前开发版本）

右上角“消息”打开分页弹窗，每页10条，保留最近7天，不设已读未读。Windows 运行或托盘驻留且登录联网时接收新消息；退出、断网和休眠期间不补弹，历史在弹窗查看。系统禁用通知不影响消息保存。点击通知重新校验任务权限。完整业务范围见[消息通知设计](../design/V2.0消息通知设计.md)。需要部署新增迁移并重新发布桌面安装包后才对使用者生效。
