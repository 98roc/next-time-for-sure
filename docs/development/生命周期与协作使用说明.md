# 生命周期与协作

网页入口 `/collaboration`，各业务页顶部显示未读通知入口。默认按项目查看选定周的安排、进展、相对最近发布版本的调整、待分配和阻塞；按人员查看当前可见范围内的跨项目分工及预计投入。未入周安排的有效分工单列未估算，不用任务数量判断忙闲。个人进展仍按源记录权限过滤，私人事项不进入总览。

## 处理生命周期

任务详情及个人事项下方有“生命周期与归属管理”。选择操作后先读取影响范围与阻止原因；填写原因并确认，服务端再次校验当前权限和版本。409时重新预览，不能直接重试旧确认。

- 团队任务删除限无执行事实、未出现在正式计划或周报且无子任务／关联个人工作。个人事项仅本人可删除，不自动完成分工，发布副本保留。删除没有恢复入口。
- 团队负责人可将任务连同子任务、关联个人工作移到本团队另一活跃项目；独立工作从个人空间的可见工作入口转移。当前在队的主负责人和参与人补入目标项目，历史退出／转交人员不自动加入。不改个人内容、状态、实际时间。
- 团队负责人或项目研发负责人可归档、恢复项目。预览列出未结束任务和独立工作；先处理再归档。归档后可查历史、整理和补记，不能新增工作、恢复执行或纳入新的计划发布。
- 团队负责人可先移出成员。移出立即撤销原团队访问，私人事项保留；协作页列出离队／停用成员仍在负责的任务、未完成分工及管理职责。通过原任务、分工和组织入口交接，不新增交接状态。
- 更换项目管理人员后，可从项目生命周期区域移出原项目成员。服务端要求保留在队且启用的项目经理和研发负责人。移出只撤销该项目角色，其他有效团队／小组身份仍按原规则计算权限。
- 团队负责人可查最近200条团队生命周期摘要。任务历史仍在项目工作页；私人删除记录不会进入团队生命周期记录。

## 站内通知

已登录网页每10秒轮询；协作页可手动刷新和标为已读。消息写入与业务同事务，投递中断时回滚并保留待投递事件，下次轮询重试。单次最多投递100个事件，单人显示当前权限内最近200条通知。唯一约束保证同事件、同账号只有一条通知。

覆盖需求待处理及处理结果、分配／转交、完成／取消、重要排期、主责变更、阻塞、认领退出、管理关联、跨项目转移、分工恢复及已发布周报补记。普通编辑、个人排序和日常拆分不通知他人。等待任务完成只提示人工解除阻塞；补记不自动修订周报。通知标题不复制私人正文，成员离队后不返回旧团队通知。

网页读取共用数据库已读状态，展示本身不标已读。此阶段不包含Windows弹窗、托盘和桌面展示去重，这些在第6阶段验证。

## 会话API

以下路径统一前缀 `/api/v1/`。修改使用当前登录会话、同源JSON和 `X-CSRF-Token`，当前不接受个人Token代替会话。

| 方法与路径 | 用途 |
| --- | --- |
| POST lifecycle/preview | 输入 intent，返回 title、impacts、blockers、confirmation |
| POST lifecycle/commands | 输入 intent、confirmation、reason、operationId；返回 objectId |
| GET lifecycle/handoff | 团队负责人当前待交接职责 |
| GET lifecycle/history | 团队负责人当前团队生命周期摘要 |
| GET lifecycle/overview?week=YYYY-MM-DD | 周一日期，按当前权限返回项目及人员总览 |
| GET notifications | 投递待处理事件并读取本人可见通知 |
| POST notifications/read | 输入 id，重复读取保持首次已读时间 |

intent 支持 `delete_task`、`delete_personal`、`archive_project`、`restore_project`、`remove_member`（objectId），`transfer_task`、`transfer_personal`（另带 targetProjectId），`remove_project_member`（objectId为账号，另带 projectId）。操作标识不得复用为不同内容；同账号完全相同请求的重试只返回已提交收据，不再次修改数据。预览后权限或影响范围变化会被拒绝。

运行 `.\scripts\pnpm.ps1 lifecycle:smoke` 验证隔离随机夹具，结束自动清理。实现、迁移及证据见[第5阶段实施记录](第5阶段实施记录.md)。
