# 第5阶段：生命周期、协作与通知

状态：已完成。日期：2026-10-14。范围：网页、会话API及MySQL。实现入口为 `apps/api/src/lifecycle`、`notifications`、`apps/web/src/lifecycle` 和对应共享契约。操作方法集中见[使用说明](生命周期与协作使用说明.md)。

## 实现与持久化

- 删除、转移、归档恢复和成员移出统一“预览→确认”流程；摘要绑定当前对象、关联版本、目标和参与人。统一组织事务锁防止权限变更与业务提交交错。
- 受限删除检查当前及历史执行事实、发布引用、子任务和个人关联。已删除个人事项的关联执行历史仍阻止团队任务删除；此路径已通过真实API验证。已发布快照不跟随源删除／转移改变。重复操作键只返回本人原请求收据，不重复写入；不同内容复用键返回409。检查清单移除增加明确确认，仍需本人保存内容。
- 跨项目转移同步子任务和关联个人工作，补入当前参与人的项目角色，保留个人事实。归档拦截新增、重启执行和新周计划发布，保留历史及补记。
- 成员移出立即生效，账号及原团队工作保留；负责人从当前未处理对象获得交接清单。项目角色可单独移出，必须保留有效管理者。
- 总览按当前可见项目汇总周安排和分工／可见个人进展，对照最近发布计划展示变更；人员投入按分工累计，未估算单列。私人正文不进入总览或团队通知。
- 业务事务写通知事件，网页轮询触发投递；投递事务失败时回滚，下次请求重试。`(event_id, account_id)`唯一约束去重，已读时间共用。当前投递是请求驱动，不依赖后台定时器、Redis或消息队列；attempts记录已提交的投递次数，不作为失败次数统计。

| 结构 | 当前用途 |

| lifecycle_events | 团队生命周期操作、原因与影响摘要；私人事项排除 |
| notification_outbox | 业务事务内的收件人快照、投递状态及次数 |
| notifications | 每账号每事件唯一消息、首次已读时间 |

## 验收证据

- `check`：严格类型、Lint、6项单元测试及所有工作区构建。
- `lifecycle:smoke`：真实HTTP及MySQL，验证关联个人事实随项目移动、非负责人转移拒绝、未结束任务／独立工作阻止归档、归档后新增及恢复个人执行拒绝、恢复项目、删除关联限制及确认范围变化409、删除幂等收据、成员即时撤权和私人保留、交接清单、项目角色移出前有效管理者约束、团队操作历史及私人隔离。
- 通知事务故障注入：投递后、提交前模拟中断，数据库回读确认未留下通知；真实HTTP重试后只产生一条，重复读取不增加。验证猜测他人通知403、已读回读、离队后无旧通知。
- 总览API验证预计投入2.50天、项目经理无权项目不返回、非周一拒绝；后续增加未入周安排分工的未估算展示。
- `weekly:smoke`：两个连续周次回归，增加正式计划引用阻止删除和已发布周报新增补记只提醒一次；原发布副本保持不变。
- `work:smoke`：原任务、分工、个人事项、鱼骨图增改移出、拆分、排序、阻塞和管理关联完整回归；增加等待任务完成通知及管理关联通知断言。
- 浏览器只操作随机验收账号：协作页、归档预览、原因输入框和确认按钮深色布局，390px窄屏无横向溢出。保存[预览截图](evidence/phase5-lifecycle-preview.png)、[窄屏截图](evidence/phase5-mobile-collaboration.png)。截图后总览位置移到通知之前，未改变控件样式；删除、转移及归档提交由API验收。
