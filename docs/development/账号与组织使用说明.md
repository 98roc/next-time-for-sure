# 账号与组织使用说明

本说明覆盖第2阶段已实现的账号、会话与组织管理。需求、分工与个人事项的当前能力及验收见[第3阶段实施记录](第3阶段实施记录.md)；周报已在第4阶段交付；个人Token API及账号页已实现，见[桌面与Agent使用说明](桌面与Agent使用说明.md)。成员移出和项目角色交接见[生命周期与协作使用说明](生命周期与协作使用说明.md)。

## 首次使用

1. 按[本地开发与启动](本地开发与启动.md)配置并迁移数据库。
2. 执行`.\scripts\pnpm.ps1 admin:init`。仅当账号表为空时允许初始化；随机临时密码写入`.bootstrap-credentials.local`，不会输出终端或覆盖已有文件。
3. 启动服务，访问`/account`。超管首次登录须修改密码；密码12～128字符，改密撤销所有旧会话，重新登录后进入`/organization`。
4. 超管创建团队及负责人账号。负责人使用临时密码登录并改密后，可以创建或关联成员、维护小组及项目角色。
5. 管理者可以重置其他成员密码、停用或启用账号；重置密码要求本人重新改密。禁止从此入口重置自己或超管账号。

本机保留一套示例团队，包含2名成员、2个小组和2个项目。随机账号及临时密码保存在`.demo-credentials.local`，均需首次改密。两个`.local`文件被Git忽略；本人改密并妥善保存新密码后可删除对应凭据文件。

## 当前边界

- 超管负责团队负责人及预设角色权限配置，可进行账号管理，不因超管身份获得业务操作权限。
- 团队负责人在获授权的本团队范围管理成员、小组和项目。已有账号关联仅接受尚未加入团队的账号，不执行隐式跨团队转移。
- 成员可同时属于多个小组。组长必须为本组成员，小组和项目成员必须属于同一团队且未停用。
- 项目成员可以兼任项目经理、项目研发负责人、研发人员；项目必须保留项目经理和项目研发负责人。
- 项目或小组角色的操作权限不能扩散到其他项目、小组或整个团队。负责人交接及策略变更在下一次后端请求中重新计算权限。
- 私人事项及个人事实接口已在第3阶段进行独立API验收，具体范围见阶段实施记录；目录权限验证本身不能代替业务验收。

## 接口与错误反馈

网页经Vite同源代理访问`/api/v1`。会话Cookie为HttpOnly、SameSite=Strict、12小时有效；本机HTTP没有Secure属性。写操作必须携带同源Origin、JSON内容类型及当前身份返回的`X-CSRF-Token`（登录不要求CSRF）。不接受Bearer替代登录会话。

| 接口 | 用途 |
| --- | --- |
| POST `/auth/login` | 登录，返回公开身份及CSRF校验值，Cookie保存原始会话 |
| GET `/auth/me` | 检查当前身份与账号状态 |
| POST `/auth/password` | 本人原密码校验、改密、撤销全部会话 |
| POST `/auth/logout` | 撤销当前会话 |
| GET `/organization` | 按当前身份返回团队目录及可见项目 |
| POST `/organization/commands` | 团队、小组、成员、项目角色、重置、禁用、权限配置 |

组织命令的`action`与完整输入契约维护于`packages/contracts/src/organization.ts`，身份输入维护于`identity.ts`。修改已有对象须带快照版本；409表示数据已变化，应刷新、核对再提交，不自动覆盖。401需重新登录；403表示来源、CSRF、首次改密或授权不满足；400表示输入及成员资格不满足；429表示同来源15分钟内达到30次认证尝试上限。

## 持久化与实现

`identity`负责密码派生、会话、认证节流和审计；`organization`负责组织命令、角色范围与目录裁剪。协议控制器只解析输入；服务在事务内鉴权和检查业务条件；SQL集中在各自仓储。

账号密码使用独立盐的scrypt派生，会话只存SHA256摘要。组织操作通过基线行锁串行化并校验版本号；业务事务采用READ COMMITTED，账号与会话的当前读保护撤销检查。组织目录读取会锁定账号行，适用于当前小团队规模；未来数据量增大时需按作用域缩小锁范围。未知异常统一脱敏，不输出SQL绑定参数。

| 表 | 用途 |
| --- | --- |
| accounts | 账号、密码派生值、团队归属、禁用及改密状态 |
| login_sessions、authentication_limits | 会话摘要、有效期及来源认证节流 |
| audit_events | 操作账号、事件、目标标识及时间，不保存密码或请求体 |
| teams、work_groups、group_members | 团队负责人、小组及多组成员关系 |
| projects、project_members | 项目及可兼任的项目角色 |
| role_policies | 固定预设角色的操作权限与版本 |

所有表及字段均有中文COMMENT，包括框架迁移记录表。`db:status`从information_schema检查遗漏；不得修改已执行迁移来变更现有库。

## 验收命令

```powershell
.\scripts\pnpm.ps1 check
.\scripts\pnpm.ps1 db:status
.\scripts\pnpm.ps1 identity:smoke
.\scripts\pnpm.ps1 organization:smoke
.\scripts\pnpm.ps1 smoke
```

回归脚本使用独立随机账号和临时监听端口，只清理自己创建的数据和进程。`organization:smoke --keep-demo`可保留示例数据；输出凭据文件存在时拒绝覆盖，避免遗失旧账号密码。真实登录测试会消耗本机来源的认证额度，不删除已有来源节流记录来绕过限制。
