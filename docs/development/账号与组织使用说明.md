# 账号与组织使用说明

> 适用当前 V2.0 开发分支；生产尚未迁移。实现与分层验收见[V2.0 实施记录](V2.0实施记录.md)，完整迁移和多端验收完成前不可作为生产发布版本。

账号与基础团队管理保留，V2 项目成员与角色配置使用[团队管理设计](../design/V2.0团队管理设计.md)规定的统一入口。

## 首次使用

1. 按[本地开发与启动](本地开发与启动.md)配置并迁移数据库。
2. 执行`.\scripts\pnpm.ps1 admin:init`。仅当账号表为空时允许初始化；随机临时密码写入`.bootstrap-credentials.local`，不会输出终端或覆盖已有文件。
3. 启动服务，访问`/account`。超管首次登录须修改密码；密码规则见[研发需求的密码与登录会话规则](../product/研发需求说明书.md#密码与登录会话)。改密撤销所有旧会话，重新登录后进入`/accounts`。新密码不能与旧密码相同；未登录时不显示返回工作空间按钮。
4. 超管在`/accounts`新增账号，再到`/organization`新增团队并选择已启用、未入团队的账号作为管理员。团队负责人使用临时密码登录并改密后，可以创建或关联成员、维护项目角色。
5. 管理者可以重置其他成员密码、停用或启用账号；重置密码要求本人重新改密。禁止从此入口重置自己或超管账号。

本地示例账号仅以忽略文件 `.demo-credentials.local` 及实际数据库为准，不将历史示例数量视为当前事实。初始化凭据在 `.bootstrap-credentials.local`；本人改密并妥善保存新密码后可清理对应临时凭据。

## 当前边界

- 超管侧栏仅提供账号管理、团队管理。账号支持新增、编辑登录名与姓名、删除、启用停用及重置密码；团队支持新增、编辑名称与管理员、删除。使用列表、搜索、行内操作与弹窗；超管目录不返回项目。
- 团队负责人在本团队范围创建成员账号、启用停用及重置其他成员密码，管理成员和项目；全局账号编辑、删除仍由超管操作。已有账号关联仅接受尚未加入团队的账号，不执行隐式跨团队转移。
- 项目成员可以兼任项目经理、项目研发负责人、研发人员；项目必须保留项目经理和项目研发负责人。
- 项目角色的操作权限不能扩散到其他项目或整个团队。负责人交接在下一次后端请求中重新计算权限。预设角色采用代码内固定规则，不开放权限配置；旧角色策略表不参与授权。
- 私人任务仅本人可见，不进入团队周报；业务权限由 V2 接口再次校验。

账号删除仅允许无团队关联、无业务关系或历史的账号，清理其会话与Token，审计保留。空团队删除保留管理员账号；有其他成员、项目或业务历史时拒绝。所有更新和删除均校验打开弹窗时的版本，冲突不覆盖已保存结果。

## 接口与错误反馈

网页经Vite同源代理访问`/api/v1`。会话Cookie为HttpOnly、SameSite=Strict，数据库与Cookie共用30天有效期；成功请求后重新检查账号和会话，在事务中延长数据库有效期，再同步Cookie。本机HTTP没有Secure属性。标记为`X-NTFS-Session-Activity: passive`的后台查询、健康探针、Bearer请求和失败请求不续期。改密和退出的清除Cookie不会被续期覆盖；已过期会话不能恢复，尚未过期的旧12小时会话可在使用时续期。写操作必须携带同源Origin、JSON内容类型及当前身份返回的`X-CSRF-Token`（登录不要求CSRF）。身份与个人Token管理仍要求登录会话；组织业务接口允许个人Bearer Token，实时执行同一身份与权限检查。

| 接口 | 用途 |
| --- | --- |
| POST `/auth/login` | 登录，返回公开身份及CSRF校验值，Cookie保存原始会话 |
| GET `/auth/me` | 检查当前身份与账号状态 |
| POST `/auth/password` | 本人原密码校验、改密、撤销全部会话 |
| POST `/auth/logout` | 撤销当前会话 |
| GET `/organization` | 按当前身份返回团队目录及可见项目 |
| POST `/organization/commands` | 基础账号、团队、成员关联、负责人、重置密码及启停 |
| POST `/v2/team` | 项目及项目成员整体配置、团队文案 |

组织命令的`action`与完整输入契约维护于`packages/contracts/src/organization.ts`，身份输入维护于`identity.ts`。修改已有对象须带快照版本；409表示数据已变化，应刷新、核对再提交，不自动覆盖。401需重新登录；403表示来源、CSRF、首次改密或授权不满足；400表示输入及成员资格不满足；429表示同来源15分钟内达到30次认证尝试上限。

## 持久化与实现

`identity`负责密码派生、会话、认证节流和审计；`organization`负责组织命令、角色范围与目录裁剪。协议控制器只解析输入；服务在事务内鉴权和检查业务条件；SQL集中在各自仓储。

账号密码使用独立盐的scrypt派生，会话只存SHA256摘要。组织操作通过基线行锁串行化并校验版本号；业务事务采用READ COMMITTED，账号与会话的当前读保护撤销检查。组织目录读取会锁定账号行，适用于当前小团队规模；未来数据量增大时需按作用域缩小锁范围。未知异常统一脱敏，不输出SQL绑定参数。

| 表 | 用途 |
| --- | --- |
| accounts | 账号、密码派生值、团队归属、禁用及改密状态 |
| login_sessions、authentication_limits | 会话摘要、有效期及来源认证节流 |
| audit_events | 操作账号、事件、目标标识及时间，不保存密码或请求体 |
| teams | 团队与负责人 |
| projects、project_members | 项目及可兼任的项目角色 |
| v2_* | V2 任务、安排、个人位置、共享文字及操作历史；授权按当前身份与项目角色计算 |

所有表及字段均有中文COMMENT，包括框架迁移记录表。`db:status`从information_schema检查遗漏；不得修改已执行迁移来变更现有库。

## 验收命令

```powershell
.\scripts\pnpm.ps1 check
.\scripts\pnpm.ps1 db:status
.\scripts\pnpm.ps1 identity:smoke
.\scripts\pnpm.ps1 organization:smoke
.\scripts\pnpm.ps1 smoke
```

回归脚本使用独立随机账号和临时监听端口，只清理自己创建的数据和进程。组织回归不保留示例数据；真实登录测试不删除已有来源节流记录来绕过限制。

当前 V2 验收记录见[V2.0 实施记录](V2.0实施记录.md)。旧表仍作为迁移来源保留，账号和团队删除检查兼容未迁移历史；这不开放旧功能。迁移完成前不能删除源表。
