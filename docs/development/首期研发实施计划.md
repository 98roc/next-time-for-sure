# 下次一定｜首期研发实施计划

状态：第1～5阶段已完成，第6阶段进行中  
版本：v1.2  
制定日期：2026-10-13  
需求基线：[研发需求说明书 v1.7](../product/研发需求说明书.md)、[产品需求说明书 v0.23](../product/需求说明书.md)  
设计基线：[已确认界面设计](../design/界面设计方向.md)

本文记录已讨论确定的研发顺序、技术约定及验收要求，不代表功能已经实现。具体业务规则以需求文档为准；实施中发现冲突应先澄清，不通过技术实现静默改变需求。

## 一、目标与交付边界

完成研发需求的全部首期功能，分阶段交付，最终在用户的Windows本机运行网页、后端、Windows客户端及外部Agent接入。

- 使用现有MySQL 5.7.35实例，创建独立的`next_time_for_sure`数据库，不修改其他项目数据。连接凭据仅放在不入库的本地配置中。
- 管理员创建账号，采用账号密码登录，支持修改密码和管理员重置，不开放自助注册；网页及桌面均联网使用，不提供离线编辑和后续同步。
- 沿用已确认的留白布局、雾蓝配色、看板交互和鱼骨式里程碑；具体视觉值维护在设计文档，不在此重复。
- 团队与个人看板分别按产品需求4.1实施：团队固定状态列，个人支持自定义分类；分类移动与执行状态变化分开处理。
- Codex、ZCode、Qoder、Workbody四个Agent兼容目标保留，本轮仅要求Codex真实接入验证；其他三个目标标记未验证，不阻塞本轮验收，不宣称已经兼容。
- 不包含正式服务器上线、微信机器人、文档平台联动及需求中明确排除的能力。

工程底座已开始实现；业务模块及完整多入口能力仍须按阶段建设和验收。本计划采用阶段验收推进，不以尚未评估的日期承诺替代完成标准。

## 二、技术与接口约定

| 方面 | 实施约定 |
| --- | --- |
| 工程与运行时 | 使用pnpm workspace，分别组织React＋Vite网页、NestJS后端、Electron桌面和MCP适配器，共享接口契约与基础UI。项目单独使用Node 24 LTS，不改变其他项目默认Node；初始化时固定依赖版本、包管理器及锁文件。脚本兼容PowerShell 5.1。 |
| 前端 | 使用React Router、TanStack Query；第3阶段采用原生拖放和显式按钮，暂未引入dnd-kit；提取共用设计变量与基础组件，不直接把原型作为正式页面。拖拽提供占位、平滑让位、失败回退和显式移动入口。 |
| 数据库 | 使用TypeORM＋mysql2及版本化迁移，关闭自动同步表结构；所有SQL和迁移在MySQL 5.7验证。允许按实际需求引入其他数据库或中间件，不将Redis、消息队列等预先设为必需或禁止项。引入时记录用途、维护成本与验证方式；现有MySQL作为起始方案，替换时同步访问层及迁移方案。后端保持模块化单体。 |
| 业务接口 | 统一`/api/v1` REST接口及OpenAPI文档，网页、桌面和Agent共用后端业务服务。外部输入运行时校验；修改携带版本号，冲突明确反馈；接收、发布等操作支持幂等，不能重复生成业务记录。 |
| 身份认证 | 网页采用服务端会话；个人访问Token随机生成、仅展示一次，服务端保存摘要。会话与Token身份分开，Token无权生成或撤销Token；每次操作检查当前身份、权限及业务状态。 |
| 确认与历史 | Agent先展示操作内容及影响范围，由用户在对话中确认，不要求跳回网页；必要确认绑定操作内容及当前版本，执行前由服务端重新校验，相关数据或影响范围变化时重新确认。个人执行事实、变更记录、发布快照分别保存；历史引用不依赖原记录始终存在。 |
| Agent与Skill | 以REST业务能力为基础，提供本地MCP stdio适配器和个人Token配置。Codex接入方式在第一阶段验证，其他三个目标保留未验证标记；Skill只编排操作，不承载另一套业务规则。 |
| 桌面与通知 | Electron复用网页与业务接口，遵循项目的上下文隔离及IPC规范。数据库事件记录驱动通知，支持重试、去重和多端已读同步；系统通知展示不等于已读。 |

Node运行时依据：[Node.js版本说明](https://nodejs.org/en/about/previous-releases)。具体依赖锁定结果及兼容验证记录在工程建立后补充，不把选型视为验证通过。

## 三、分阶段交付

第1、2、3阶段的证据分别见[工程验证记录](第1阶段验证记录.md)、[账号组织验证记录](第2阶段验证记录.md)、[任务与个人执行记录](第3阶段实施记录.md)。各阶段同时交付页面、接口、数据库、必要测试和说明；第4阶段已完成周计划、人工标签与周报两周演练；见[第4阶段实施记录](第4阶段实施记录.md)。第5阶段生命周期、协作及站内通知已验收，见[实施记录](第5阶段实施记录.md)。

| 阶段 | 主要工作 | 完成标准 |
| --- | --- | --- |
| 1. 研发基线与工程底座 | 建立需求—实现—验收对照表；确定对象关系、状态转换和权限矩阵；初始化工程、迁移、本地配置及检查脚本。盘点Codex环境，尽早验证最小工具调用；认证随账号及Token能力验证。 | 前后端可启动、数据库可迁移；工程检查通过；明确Codex可用环境及其余三端未验证状态。 |
| 2. 账号、组织与权限 | 登录退出、改密和重置；超管初始化；团队、小组、预设角色权限、项目成员及多角色权限合并；落实多小组成员关系及固定权限边界。建立会话撤销、账号禁用和操作审计。 | 不同角色可完成建团队、建项目、加成员；越权和私人事项访问被后端拒绝。 |
| 3. 需求、任务与个人执行 | 需求提交、补充、撤回、接收、暂缓和重提；团队任务、一层子任务、人员分工、认领、退出、转交；个人任务、检查清单、进展、阻塞、开始结束及补记。按需求3.2落实每条分工的负责小组和跨组调整；支持带发生日期及归属周的多条进展。同步完成团队状态看板、个人分类看板与鱼骨图。 | 跑通“需求接收→分配→个人执行→整体结束”；关联状态正确，个人事实不被管理操作代改；说明和完成标准可留空。 |
| 4. 周计划与周报 | 团队共享草稿、按人按周安排、预计投入、未完成分工结转、发布基线及调整；手动计划外标签；周报归集、人工整理、合并排除、增量生成、修订发布和复制文字；按需求4.8落实已发布周报公开与草稿、源记录权限隔离。 | 完成两个连续周次的业务演练；重复生成不重复汇总、不覆盖人工整理，已发布版本不被后续修改改写。 |
| 5. 生命周期、协作与通知 | 重开、取消、受限删除、跨项目转移、归档恢复、成员移出和职责交接；团队总览及业务事件站内通知；评论、提及、手动催办及附件不纳入首期。完成通知重试、去重和已读同步。 | 项目和成员变动后权限立即生效；历史仍可查询；归档前检查完整，通知不会因重连重复生成。 |
| 6. Windows与Agent完整接入 | Electron复用网页，提供安装包、托盘驻留、明确退出和系统通知；完成Token管理、全部业务操作的Agent等价能力，以及需求、团队任务、周报三类Skill。 | 桌面实际安装运行；逐项核对网页与Agent能力；Codex记录版本、配置、成功调用、必要确认和拒绝场景；其他三个目标标记未验证。 |
| 7. 综合验收与交付 | 全链路、多角色、并发、历史、手机网页和桌面回归；补齐安装、启动、迁移、备份恢复、Agent配置与故障定位文档。 | 从干净项目库完成初始化和完整业务演练，交付可运行工程、Windows安装包、测试结果与验收记录。 |

阶段依赖与推进方式：

- 通知事件、审计及Agent操作契约从前期建立，各业务模块完成时同步接入，避免最后集中补做。
- 第3阶段具备执行所需的整体结束及停止执行限制；第5阶段补齐完整生命周期、历史处理与组织变更场景，不能在前期允许绕过已明确的限制。
- 第1阶段的Agent工作用于验证接入可行性，不替代完整认证、业务能力及Skill验收。目标工具不支持既定方式时，先明确适配方案；不静默删减兼容范围。
- 本轮仅Codex接入验证作为验收前提；其他Agent环境缺失不阻止本轮交付，但对应兼容目标不得标记已验证。

## 四、必须覆盖的验收场景

| 范围 | 重点场景 |
| --- | --- |
| 权限 | 多角色合并但不跨范围；项目经理不能直接查看无权访问的个人源记录，但可查看全团队已发布周报中的整理内容；草稿仍按原权限访问；多组身份不授予其他组负责分工的调整权；角色配置不能突破固定权限边界；私人事项仅本人可见；移出成员、移出项目、禁用账号、撤销或过期Token后拒绝访问。 |
| 状态与关联 | 整体结束不伪造个人完成；新增个人工作按规则恢复本人分工；拆分、退出、转交和重开不重复记录或误改时间；管理者不能代改个人执行事实。 |
| 并发与幂等 | 需求接收与修改、撤回竞争；重复认领、重复发布、多人编辑草稿；冲突明确反馈，已保存结果不丢失。 |
| 计划与历史 | 跨周仅结转有效未完成分工；多组成员的分工、预计投入及来源工作不重复统计；多条进展按归属周汇总；周报保留人工合并和排除；删除、转移、补记、重新生成不破坏发布快照。 |
| 页面交互 | 团队跨状态列移动执行对应业务操作，个人分类移动不改变执行状态；拖拽权限和失败回退、键盘移动、空内容隐藏、同日多个里程碑、跨视图数据一致性、浅深色及手机窄屏布局。 |
| Windows客户端 | 实际安装与启动；关闭和最小化后继续接收通知；托盘重开及明确退出；当前用户隔离、通知去重、已读同步。 |
| Agent与Skill | 本轮在Codex验证查询、写入、必要确认、越权拒绝及三类Skill；核对完整业务能力覆盖，明确排除个人Token管理；ZCode、Qoder、Workbody保持“未验证”。 |

自动化检查重点覆盖权限、状态、事务、并发、来源归集和发布快照；视觉、桌面系统能力及真实Agent接入分别保留运行证据。验收记录区分静态检查、自动化测试、实际运行和数据库执行结果。

## 五、执行与交付约定

- 首个执行目标是第1阶段的可运行工程底座，不一次性堆叠全量页面。
- 需求—实现—验收对照表逐项关联需求章节、实现入口和验证结果；各阶段结束更新实际状态及剩余问题，不用计划文字充当实现事实。
- 需求、研发需求及设计文档已同步本轮确认规则；工程建设及实际验收仍待实施，不以文档同步代替功能交付。
- 数据库迁移仅针对项目独立库，执行前核对目标；本地配置、账号密码和Token不进入源码、文档或日志，示例配置不包含真实凭据。
- 保留已有未提交修改；Git提交、推送及正式部署按授权执行。
- 每阶段验收后清理确认无用的代码、脚本和临时资源，提交Git后再开始下一阶段。验收优先使用真实API脚本和数据库回读，页面只做必要检查；可保留便于试用的示例数据与本地私有凭据。
- 最终交付包含可运行工程、Windows安装包、三类Skill及Codex配置说明及其他三端未验证清单、迁移及启动脚本、备份恢复说明、验收对照表和未解决问题记录。全量完成必须同时具备业务、桌面和Codex的实际验证证据。
