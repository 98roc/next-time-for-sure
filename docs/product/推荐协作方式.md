# 推荐协作方式

本文基于 PM 团队的实际工作方式整理，供同时负责多个项目的研发团队参考。团队可按实际情况调整小组数量、人员配置和协作节奏。

本文描述协作方式；系统操作与权限以[产品需求说明书](需求说明书.md)为准。

## 1. 团队与项目分工

团队由团队负责人统筹，按前端、后端等职责设置研发小组。各组由组长协调工作，可结合老带新的方式开展协作。

团队同时负责多个项目。每个项目通常有一名项目经理和一名主要的研发负责人。研发负责人负责对接需求、维护任务和里程碑，通常由组长担任，也可以由其他成员担任。组员主要负责执行任务。

## 2. 每周安排与复盘

通常在周五，由团队负责人组织各组组长总结本期工作、安排下期任务。遇到节假日或调休时，按实际工作日调整。

具体配合方式如下：

1. 后端组长提前整理下期任务，涉及前端的部分先留空，发给团队负责人。
2. 各组长在周会前更新相关项目的里程碑。
3. 团队负责人与组长一起复盘进展，结合预计天数、任务难度和人员能力，判断各组工作量是否合适。
4. 需要前端配合的任务，与前端组长沟通后安排人员和工作内容。
5. 安排确定后，在周会上发布任务。

## 3. 任务执行与完成

任务按项目管理。前后端共同参与的工作，小任务可以合并记录，较大的任务可以拆开。

组员通过口头或聊天反馈进展，由组长统一更新记录。成员也可以用自己的工具或笔记管理个人待办，团队不作统一要求。

任务是否完成，由任务归属人判断。同一任务由前后端共同承担时，各自确认自己的部分，全部完成后，该任务才算完成。

任务可以设置优先级和截止日期，但不要求必填。没有特殊说明时，本期任务默认周五完成。明确跨周的任务保留同一条记录，约定本期结束时达到的累计百分比，例如从已完成 30% 推进到 60%。遇到节假日或调休时，完成时间随本期安排调整。

## 4. 里程碑管理

每个里程碑属于一个项目，可以对应一个或多个任务。

任务全部完成，不代表里程碑自动完成。项目研发负责人需要结合实际交付情况，单独确认里程碑是否完成。

## 5. 临时任务与调整

执行过程中，项目经理可能临时提出新任务或调整要求，由项目研发负责人先判断、协调执行。

影响原安排时，项目研发负责人和组长协调调整，原任务可以顺延；涉及跨组协调或重要交付时，再交团队负责人统筹。

临时新增任务起初作为计划外任务管理。如果任务持续时间较长或比较重要，会将其纳入里程碑，之后不再算计划外。即使没有纳入里程碑，只要下期正式安排继续执行，下期也不再算计划外。

## 6. 日常记录

PM 团队目前主要维护两份文档，均按项目组织，项目一一对应：

- **里程碑文档**：记录各项目的里程碑。
- **周报文档**：记录各项目的本期工作总结和下期任务安排。
