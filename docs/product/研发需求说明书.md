# 下次一定｜V2.0 研发需求

确认日期：2026-10-16。本文维护产品规则与研发约束基线；实现、生产迁移及分层验收状态见[实施记录](../development/V2.0实施记录.md)。

业务范围见[产品需求](需求说明书.md)，详细操作规则见[四个入口设计](../design/V2.0产品结构设计.md)。本文件只维护跨入口契约、保留基础能力及验收要求，不重复各页面规则。

## 1. 同一业务、同一结果

- 项目、我的工作、周计划及 Agent 引用同一项目任务，状态同步；个人分类和顺序是本人视图，周计划排序是团队共享数据。
- 任务与区间是多对多安排，预计天数属于具体安排，不能将任务表中的单一区间字段当作完整模型。创建任务与首个安排同事务；改排须同时校验原、目标区间，不能短暂留下无安排任务或覆盖已有安排。
- 任务创建、批量新增、待建转换共用字段校验和权限。待建转换保留原创建人，操作人单独记录；重复提交不重复生成任务。
- 项目任务状态变化记录前后状态、发生时间、执行人和实际操作者。负责人代改不伪造操作者，历史状态不因回退或再次完成被覆盖。
- 周期预计投入与任务累计实际投入分别持久化，零值与未填写区分。完成状态、结果字段、周期安排及个人分类在同一事务内保存；按钮、拖拽、详情、新建已完成项目任务和 Agent 共用后端完成校验。具体字段与历史兼容规则见[项目设计](../design/V2.0项目设计.md#投入与完成结果)。
- 区间总结读取该区间安排与实际执行事实；已结束区间按结束时状态回看。我的工作完成列读取本次实际完成日期，两者查询语义不同。
- 私人子任务不进入正式任务聚合、团队周报或投入统计，主子状态独立。当前清单与不可变历史同事务保存，删除和改派不转移或清理本人历史；日报按所选日末本人事实生成，详细规则见[我的工作设计](../design/V2.0我的工作设计.md)。
- 删除业务对象不等于清除必要历史。当前列表及安排解除后，历史总结、审计及已保护人工文字仍按规则可追溯；生产取消功能的数据清理由专门迁移处理。

### 统一默认排序与手动排序

- 项目默认按创建时间倒序（新项目在前）；正式任务、待建任务及个人任务默认按优先级升序（1 最高），同优先级按创建时间正序（较早在前）。相同时间以固定标识稳定排列。旧项目仅凭创建审计补齐创建时间，无法还原的排在已知时间之后。
- 未手动排序时，新增和优先级调整动态遵循默认规则；拖拽自动保存手动顺序，新进入列表的任务及新项目置顶，已有对象相对顺序不变，修改优先级不自动挪动。连续新增时较新的在前。
- 提供“恢复默认排序”，恢复后新增及优先级调整重新参与默认排序；按钮作用于标明的完整列表或分类，不只重排当前筛选结果。恢复和拖动都校验版本，旧请求不能覆盖新结果。
- 项目页、周报与周计划、我的工作分别保存顺序。项目汇总与里程碑总览共用同一项目顺序，包括默认排序和已保存的手动排序；项目页汇总和详情共用项目内正式任务顺序，待建任务单独保存；周报项目组按团队跨所有周期共用且左右列一致，任务按项目和日期区间保存、项目/人员视角共用；个人顺序按本人分类保存。
- 项目页与周报中的跨项目排序由团队负责人维护，项目内正式/待建任务排序由团队负责人或本项目研发负责人维护。个人顺序仅本人调整。筛选重排保留隐藏对象的相对顺序及位置；恢复默认作用于完整范围。
- 升级保留已有共享排序及已有个人分类顺序；新列表使用默认排序，已有列表可通过“恢复默认排序”启用新规则。

## 2. 权限与并发

- 每次读写都校验当前身份、团队/项目、角色及状态，页面显隐、旧查询结果和 Token 都不能替代实时鉴权。
- 任务、安排、里程碑及成员关系的变化在事务内重新检查；移出成员与新增任务并发时，不得留下被移出成员的未完成安排。
- 版本冲突明确反馈，保留编辑草稿并要求刷新核对，不能静默覆盖。批量新增须明确整批成功或失败，不虚报部分成功为全部成功。
- 共享排序不能用只含可见项目的列表覆盖全团队顺序；项目内排序只调整管理范围，跨项目组顺序由团队负责人维护。个人排序不影响共享排序。
- 团队周报手工文字按团队及总结/计划区间组合保存，私人日报按账号及日期保存，来源变化单独标记。两者复用文字编辑保护，重新生成预览绑定源版本，确认时再次检查；旧预览不能覆盖新来源，复制只能复制当前显示文本。
- 子任务当前读写检查任务当前执行人；所有私人历史、日报与偏好查询强制绑定认证账号，不接受任意 ownerId，团队负责人不能读取。清单、文字、个人偏好分别版本校验；完整清单保存明确声明删除标识，版本变化后须重新核对。
- 其他成员只能生成自己权限范围的文字，不能通过全团队共享自由文本泄漏无权项目；共享整稿由团队负责人查看维护，不自动给受限成员开放整稿。
- 删除、里程碑完成/重开、解除关联、取消安排及日期调整等需要确认的操作，确认绑定具体内容、影响与数据版本。

## 3. 账号、会话与 Token

### 密码与登录会话

- 管理员创建账号，不开放自助注册；首次登录或重置后要求本人改密。新密码为 8—128 字符，包含大写、小写字母和数字，不允许与旧密码相同；旧凭据按现有兼容规则处理。
- 会话使用 HttpOnly、SameSite Cookie 和服务端摘要；有效期 30 天，成功的活跃请求同步续期数据库及 Cookie。后台查询、健康探针、Bearer 和失败请求不续期，已过期会话不能恢复。
- 改密、禁用、退出及撤销按现有规则立即失效，写操作保留同源及 CSRF 检查。当前 HTTP/HTTPS 实现限制见[部署说明](../development/Docker部署.md#边界与验证口径)，不是新增 HTTPS 支持的声明。
- 超管管理全局账号和团队，团队负责人仅管理本团队账号及成员。有关联或历史的账号禁止物理删除；停用不能删除该账号的任务和历史。团队成员移出与项目成员移出不是同一命令，不能扩大套用项目移出的前置条件。

### 个人 Token 与 Agent

- Token 只代表所属用户的当前权限，不单设只读、读写或项目范围；按次验证账号、当前角色、到期和撤销。
- 本人通过网页登录或桌面登录生成、查看列表和撤销；完整 Token 只展示一次、只存摘要，不进入日志。可设到期或永久，永久须明确风险提示。Agent 不能管理 Token。
- 保留外部 Agent 对 V2.0 网页业务的等价操作能力；Controller/MCP/Skill 不复制业务规则。必要确认在对话完成，仍由后端验证具体影响和版本。
- 三个 Skill 已改为 V2 待建事项、单执行人任务和周报与周计划；取消需求审批及旧命令，工具只调用当前严格契约。
- 实际兼容证据按客户端分别记录；旧 MCP 协议通过不能代替真实客户端写入验收，见[V1 证据摘要](../archive/v1/README.md#3-已有验证证据)。

## 4. 桌面及工程基础

- 网页和 Windows Electron 复用业务界面及后端；保留连接配置、托盘、明确退出、站点会话隔离及安装包更新，不提供离线写入。旧通知链路已退役；新增消息与业务变更同事务、同幂等边界生成，规则见[消息通知设计](../design/V2.0消息通知设计.md)。桌面主进程读取当前会话消息，首次连接、换号和断线恢复建立游标，不补弹历史。
- Electron 上下文隔离、受限 IPC、外部输入运行时校验及日志脱敏继续遵循[项目规范](../../AGENTS.md)。
- 使用项目固定 Node/pnpm 及 PowerShell 5.1 脚本，保留 NestJS 模块化单体、React/Vite、MySQL 起始方案。数据库版本化迁移，禁用自动结构同步，所有表字段提供中文 COMMENT。
- 历史区间锁定按团队时区的日期判断，现有团队使用 Asia/Shanghai；展示完整起止日期，不以客户端系统时区随意划分历史。

## 5. 验收要求

| 范围 | 必须证明的结果 |
| --- | --- |
| 任务 | 单执行人、首个必填安排、三个入口同一任务、负责人代改留痕、回退后创建人删除条件正确。 |
| 投入与完成 | 多周期估算不串值、零与空区分、完成必填实际投入、默认及保留 AI 档位、私人任务无投入字段、历史空结果兼容、取消与失败不部分写入。 |
| 个人视图 | 默认分类唯一、自动进入与手动落点优先、最后分类保护、稳定重排、私人内容隔离。 |
| 子任务与日报 | 仅本人可见、完整清单增删改排、主子状态独立、完成时间不因改名重排重置、改派不转交、跨日历史保留、日期模式记忆、项目默认及个人排序、文字来源与并发保护。 |
| 区间 | 最后安排不可取消、跨区间保留来源、历史结束状态、计划外识别、日期锁定、边界调整影响及并发。 |
| 里程碑 | 任意本项目研发负责人确认、未完成任务阻止完成、任务回退不自动重开、核验提示、新增未完成关联先重开。 |
| 共享协作 | 多人排序与文字冲突不覆盖、受限用户不泄漏其他项目、人工文字及重新生成预览保护。 |
| 组织 | 两种项目负责人各至少一人、兼任与多负责人、移出前检查、停用即时撤权、历史归属保留。 |
| 迁移 | 旧新映射及数量对账、异常显式处理、重复执行、数据库回读、备份恢复演练。 |
| 各端 | 类型/Lint/测试/构建、真实 API/数据库、必要浏览器、Electron 和外部 Agent 分别给证据。 |

未完成验收应具体标明层次，不用原型通过替代业务验收；技术映射和剩余边界见[迁移准备](../development/V2.0迁移与研发准备.md)。
