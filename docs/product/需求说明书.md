# 下次一定｜V2.0 产品需求

确认日期：2026-10-16。状态：已确认的开发目标，尚未完成正式实现或生产迁移。原 V1 需求已压缩至[历史基线](../archive/v1/README.md)，不能再作为新增业务的默认来源。

## 1. 范围与入口

V2.0 面向小型研发团队，以同一条项目任务连接安排、执行与总结，减少多人分工和个人工作副本带来的重复维护。

| 入口 | 保留能力与唯一详细规则 |
| --- | --- |
| 我的工作 | 项目任务、仅本人可见的个人任务、状态分类、默认分类、个人排序和完成区间；见[我的工作设计](../design/V2.0我的工作设计.md)。 |
| 周报与周计划 | 团队日期区间、总结与计划双栏、项目/人员视角、预计天数、共享排序和文字版；见[周报与周计划设计](../design/V2.0周报与周计划设计.md)。 |
| 项目 | 项目汇总、单执行人任务、批量录入、待建任务、里程碑及总览；见[项目设计](../design/V2.0项目设计.md)。 |
| 团队管理 | 成员账号、项目基础信息、多位项目负责人、成员移出和可选文案；见[团队管理设计](../design/V2.0团队管理设计.md)。 |

上述设计和[组件与交互规范](../design/V2.0组件与交互规范.md)共同构成 V2.0 基线，原型只用于展示。基础账号登录、权限、Token、审计及现有网页/桌面/Agent 接入保留，具体契约见[研发需求](研发需求说明书.md)。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 项目任务 | 项目中的一条正式工作，只对应一名执行人，至少保留一个日期区间安排；跨入口共用。 |
| 个人任务（私人任务） | 不属于项目，仅本人可见、维护，不进入项目汇总或团队周计划。 |
| 待建任务 | 尚未明确执行人或日期区间的项目事项；不是需求审批流程。 |
| 日期区间 | 团队维护的连续、不重叠的起止日期；自然周是默认生成方式，不是固定七天约束。 |
| 区间安排 | 同一项目任务在某区间的安排关系及该区间预计投入；跨区间不复制任务。 |
| 里程碑 | 独立的项目阶段目标，关联任务作为达成条件之一，由本项目研发负责人手动确认。 |
| 团队负责人/团队管理员 | 同一团队管理角色，不新增第二种权限身份。 |
| 项目研发负责人/项目经理 | 项目角色，可各有多人并兼任；与任务执行人、创建人不同。 |

任务不设置额外“任务负责人”或“提出人”字段，模板中“负责人”表达该任务执行人，不据此新增责任层级。

## 3. 权限总边界

- 普通成员可以查看本人参与项目的全部任务、里程碑、待建任务和周安排；不能查看无关项目。人员视角汇总同样先按项目范围裁剪。
- 团队负责人在本团队、项目研发负责人在本项目维护安排和任务，并可替执行人开始、完成或回退项目任务；记录实际操作者，不伪装成本人操作。
- 普通执行人仅维护本人项目任务状态及个人视图；任务创建人另享有已明确的未开始任务删除权限。项目经理不因查看权限获得研发安排权。
- 个人任务始终仅本人可见、维护，管理者代改项目任务的规则不扩展到私人任务。
- 多角色按作用范围合并；超管继续管理账号与团队，不自动进入团队业务。
- 共享文字维护权限、里程碑确认权限及项目成员移出条件分别由对应设计维护，不以本节概括替代具体限制。

## 4. 取消的业务

除 V2.0 文档明确保留的能力外，V1 其他业务全部取消，不因现有实现或旧文档存在而继续保留。

| 取消能力 | 替代或边界 |
| --- | --- |
| 小组、组长、小组归属及直属/小组分工 | 以团队和项目角色安排单执行人任务。 |
| 需求审批、补充、暂缓、拒绝、领取流程 | 由待建任务收集并直接转换。 |
| 任务主负责人、多人员分工、认领退出转交、父子任务、关联个人事项拆分联动 | 多人工作分成多条独立项目任务，三个入口引用同一任务。 |
| 任务说明、完成标准、检查清单、独立进展记录、累计进度、实际工时与手工时间补记 | 保留名称、状态及必要状态历史；文字版可自由描述，不反写任务。 |
| 周计划/周报发布、定稿、修订发布、自动结转、人工多维标签 | 保存即生效、手动跨区间安排、基于实际安排及执行事实的计划外提示。 |
| 阻塞、依赖、任务取消业务状态、跨项目转移、项目归档恢复、独立交接流程、独立团队总览 | 仅保留三个任务状态、明确的删除规则、项目汇总及项目成员直接移出。 |
| 业务通知中心及其桌面业务推送 | 页面当前操作反馈、文字未同步和里程碑核验提示仍保留，不扩展为通知系统。 |
| 内置聊天助手、文档平台联动、附件、评论、提及、自动排期和自定义角色 | 不纳入此次 V2.0；公共能力编码规范不意味着新增对应业务。 |

设计中只提出方向而未约定契约的能力，例如私人任务转项目，仍须先闭合规则，不因一句设想自动进入可编码清单。
